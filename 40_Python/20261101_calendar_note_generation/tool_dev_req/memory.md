# 开发笔记（memory）

> 给以后接手的人 / AI 看：下面的规则都是从 `template` 里的模板反推出来的，改代码前先读一遍。

## 1. 需求要点（原文见 `calendar_note_generation.txt`）

- 输入年份 1970-2100 → 输出 `output/月度记事表_年份.xlsx`（年份前带下划线）。
- 第一页：12 个月，每月固定 7 行（1 标题 + 1 星期 + 5 日期），行列数固定，行高列宽照模板。
- 日期格：`日号 农历` 同一行、空格分隔；有节日/节气则替换农历；节日和节气同日则两者都显示、节日在前。
- 绕回第一行的日期用 `(w周次)` 标注（原来写的是 `(weekNN)`，为了省宽度改短）。
- 第二页：照模板，不改内容。
- 入口只有 `01_Run.bat`，自动找 Python。
- 依赖：`dependencies.txt` + `scripts/check_dependencies.py` 自动安装。

## 2. 模板（`template/月度记事表_2026.xlsx`）

**做法：直接 load 模板再改写内容**，不重新建样式。好处是样式永远和模板一致，用户改模板样式就自动生效。

| 项目 | 值 |
| --- | --- |
| 工作表 | `Sheet1`（日历，程序只动它）、`Sheet2`（说明页，原样保留） |
| 区域 | A1:H84（12 × 7 行） |
| A 列宽 | 5；B~H 列宽 18.53125（XML 里是一条 `<col min=2 max=8>`） |
| 行高 | 标题 18 / 星期 18 / 日期 103.5 |
| 标题 | 合并 `B{n}:H{n}`，文本 `%d 年 %d 月    事件记录`（月后面 4 个半角空格） |
| 周次格 | `Week\n01`（换行 + 两位补零），等线 9 加粗居中、自动换行 |
| 日期格 | 等线 11，靠左靠上；程序额外打开 `wrap_text`（见下） |
| 边框 | 整格细线，颜色 indexed=64（自动） |
| 页面 | A4（paperSize 9）横向，缩放 100% |
| 页边距 | 页眉 0.8cm、页脚 0.3cm、上 2.4cm、下 0.9cm、左右 0.6cm（模板第二页写的就是这些值） |

注意：模板原来的标题是「时间记录」，是错别字，用户已在 2026-11-01 改成「事件记录」；
代码里的 `TITLE_TEMPLATE` 必须跟着改，否则会被写回错别字。

模板文件名带年份（`_2026`）只是为了好认；程序把所有内容都重写，任何年份都行。
`generate_calendar.template_path()` 先找 `月度记事表_2026.xlsx`，找不到就取 `template/*.xlsx` 里排序第一个。

## 3. 周次与「绕回第一行」的算法（关键，别凭直觉改）

1. **周 1 = 包含 1 月 1 日的那一周**，每周从周一开始；全年通常 53 周。
   周次 = `(日期 - 第1周周一).days // 7 + 1`。
2. 每个月的 5 行，行内周次是 `start_week .. start_week+4`，其中
   **`start_week` = 1 号所在的那一周**（1 号是周一也直接从第一行开始写，不再整体下移一周）。
   - 也就是说：1 号总是落在第一行，列号 = `1 号是星期几`。
   - 历史坑：最初为了贴旧模板里 2026 年 6 月的排版（那一月 1 号是周一，模板把 29、30 号绕到了
     第一行），我加了「1 号是周一时 start_week 减 1」的规则。用户在 2026-11-01 指出这是 bug
     （2027 年 3 月 1 日是周一，本该从第一行写到第五行，却整月下移、月末绕回），已删除该规则。
     模板里 2026 年 6 月现在仍是旧排版，但程序会把整页内容全部重写，所以不影响输出。
3. 5 行装不下的日期（最多 3 天），从左到右填进**第一行的空格**。
   在 `calendar_layout` 里，这种单元格存的是 `(日号, 真实周次)` 元组（其他格子是 int / None），
   由 `generate_calendar._day_text()` 渲染成 `30 十月廿二 (w49)`。
4. 1984、2012、2040、2068、2096（闰年且 1 月 1 日是周日）按此定义有第 54 周，12 月会出现 `(w54)`。
   需求写的「总周数 53」是常见情况；这里选择如实显示，而不是硬压成 53。

## 4. 农历 / 节气 / 节日

- 用 **`lunar-python`**（六 tail，纯 Python，覆盖 1900-2100）算农历和二十四节气；
  `Solar.fromYmd(y,m,d).getLunar()` → `getMonthInChinese()` / `getDayInChinese()` / `getJieQi()`。
- **节日清单自己维护**（`scripts/lunar_labels.py` 顶部），不用库里的 `getFestivals()`，
  因为库的列表含情人节、愚人节、感恩节等，不符合「国内节日」的口径。
  - 公历：元旦、妇女节、植树节、劳动节、青年节、儿童节、建党节、建军节、教师节、国庆节
  - 农历：春节、元宵节、龙抬头、端午节、七夕节、中秋节、重阳节、腊八节
  - 除夕：判断「后一天的农历是正月初一」
  - 闰月不算节日（`lunar.getMonth() > 0` 才算）
- **故意没放「清明节」**：清明本身就是节气，放了会显示成「清明节 清明」，重复又占宽度。
- 优先级：**节日 > 节气 > 农历**；节日和节气同一天时两个都输出，用空格连起来（`春节 立春`、`重阳节 霜降`）。
  1970-2100 里共有 82 天属于这种重合。
- 一天只算一次，`lunar_labels.YearLabels(year)` 预先算好全年（约 0.3 秒），格子只查表。
- 需求给的验收例子已对齐：2026 年 10 月 `17 九月初八` / `18 重阳节` / `23 霜降`，
  2026 年 11 月第一行 `30 十月廿二 (w49)`，1992-02-04 `4 春节 立春`，1993-10-23 `23 重阳节 霜降`。
- 最长的格子文本实测是 `30 闰二月初九 (w14)`（14 个字符），列宽 18.53 装得下；
  日期格仍保留 `wrap_text=True` 作为兜底，万一以后加了更长的节日名也不会被隔壁格子截断。

## 5. 打印（踩过的坑）

- 模板第二页给出了自定义页边距（cm），代码里 `PAGE_MARGINS_CM` 按同样数值设置，并显式写 `scale = 100`。
- **不要自己设 90% 缩放**：一开始我按「一个月 553.5 磅 > A4 横向可打印高度 501.8 磅」算出要缩到 90%，
  结果反而把月份切开了（90% 时一页能塞下「1 个月 + 下个月的表头」，月度边界错位）。
  实测模板本身在 100% 下就是**一个月一页**，90% 才是错的。
- 验证方法（Excel COM + PyMuPDF）：
  1. `$wb.ExportAsFixedFormat(0, $pdf)` 导出 PDF；
  2. 用 PyMuPDF 逐页取文字，确认每页只有一个 `2026 年 X 月` 标题 → 12 页日历 + 1 页说明。
- 注意：用 Excel COM 导 PDF / 截图时，如果同一个 Excel 进程里先做图表截图再导 PDF 会报 `0x800A03EC`，
  分开做即可；COM 进程偶尔退不掉，会留下 `~$xxx.xlsx` 锁文件，导致下次写入 PermissionError（提示信息已覆盖这种情况）。

## 6. 代码结构

- `scripts/calendar_layout.py`：纯计算，不依赖 openpyxl。`build_year(year)` 返回
  `[(月份, start_week, 5x7 网格), ...]`，网格里是 int 日号 / `None` / `(日号, 周次)` 元组；
  `day_number(entry)` 取回日号。
- `scripts/lunar_labels.py`：节气 / 节日 / 农历的显示文字（含「节日 节气」合并）。
- `scripts/generate_calendar.py`：读模板 → 填 12 个月 → 设页面 → 存到 `output`。
- `scripts/check_dependencies.py`：读 `dependencies.txt`，缺就 `pip install -r`，失败换清华镜像。

## 7. 验证清单（改动后请重跑）

3. 打印：导 PDF，确认 12 个月各占一页 + 1 页说明。
