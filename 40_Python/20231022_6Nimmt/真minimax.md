## 0. 一句话

对随机对手，最优策略能赢 **91%**；换成会打的对手，这个 91% 一文不值——
因为**同时出牌 + 完全信息**意味着：只要你的策略是确定的，对手就能算出你要出哪张牌，然后专门克你。

---

## 1. 「minimax」到底指什么

### 1.1 它*不是*「每一步取最小最大」

在象棋那种**轮流走**的博弈里，可以写 `max_a min_b`：我走一步，对手走一步，交替。
6 Nimmt 不是——两人**同时**出牌。同时出牌时 `max_a min_b` 没有意义，因为对手不是"看了我的牌再回应"。

正确的东西是：

```
v = min_x  max_y   xᵀ M y
```

- `x` 是**我的混合策略**（我手里的每张牌被选中的概率）
- `y` 是对手的混合策略
- `M[a][b]` 是我出 a、对手出 b 时的收益

`min_x max_y` 的含义：**我先公开一个随机化方案**，对手看到方案后选最狠的应对。要让他最狠的应对也不赚，我就得选好这个方案。
注意顺序是 `min` 在外、`max` 在内——这就是"同时出牌"和"轮流走"的数学差别。

von Neumann 的 minimax 定理保证：

```
min_x max_y  =  max_y min_x
```

所以"我防得住"和"他攻得破"是同一个数，这个数就是**博弈值**。

### 1.2 先做「零和化」

有个坑必须先说清楚：**两个人都想少吃牛头，这个博弈不是零和的**——总罚分不固定，一个局面上限 19 分，但两人加起来吃掉多少要看怎么打。

零和博弈才谈得上"单一的最优值"。所以要换一个收益：

```
u = 我的罚分 − 对手的罚分        （u 小 = 我领先）
```

`u_我 + u_对手 = 0`，这就零和了。它就是"谁赢"的连续版（`u < 0` 就是我赢）。

⚠️ **注意这与"我自己最少罚分"不是一回事。** 目标函数换成了"赢多少"，后面会看到两者的最优策略确实不同。

### 1.3 一个局面 = 一个矩阵博弈

在状态 `s`（桌面两行 + 我的手牌 H + 对手手牌 O）：

```
M[a][b] = 这一回合按规则结算后「u 的增量 + V(下一局面)」
```

矩阵大小 = `|H| × |O|`，最多 `5×5`。解这个矩阵博弈得到值 `v(s)` 和我的混合策略 `x(s)`。

然后按回合倒推（5 回合、每回合必消耗两张牌 → 状态图是 DAG）：
先算"只剩 1 张牌"的局面，再算 2 张、3 张……和上一篇的倒推完全一样，只是每个节点从
「`min_a` + 平均」换成了「解一个矩阵博弈」。

### 1.4 为什么必须混合

因为**这个游戏是完全信息的**：开局 12 张牌全发完，桌面公开，我的手牌你也看得见，
所以对手可以反推出我手里是什么。再假设对手知道我的策略（打几局就能摸出来），
那么**只要我在每个局面固定出一张牌，对手就能在出牌前算出我出哪张**，然后挑一张最优的克我。

混合策略的作用就是让"我要出哪张"变成一个对手猜不到的量。这不是玄学，是让对手的最优应对
里出现一个他无法预测的变量——代价是我自己也得接受随机的结果。

顺带一个实现上的观察：**只有"同时出牌"那一步需要混合**。
当某人被迫吃行、自己挑一行时，那是他一个人在做顺序决策，没有信息不对称，纯策略就够。

## 2. 算法实现

```python
def game_value(M):                      # min_x max_y xᵀ M y
    row_guarantee = min(max(row) for row in M)                      # 我能保证的上界
    col_guarantee = max(min(M[i][j] for i) for j)                   # 对手能保证的下界
    if 两者相等:                                                      # 纯策略鞍点
        return 值, one-hot
    return linprog(...)                 # 否则解 LP：min v s.t. Σx_i M[i][j] ≤ v, Σx=1, x≥0
```

三条注意：

1. **鞍点判定别写反**。第一版我把 `max_i min_j` 和 `min_j max_i` 当成上下界，
   它们**不是**一对界（正确的界是 `min_i max_j` 和 `max_j min_i`）。
   后果不是值算错，而是**返回了一个"最大化自己最坏情况"的纯策略**——值看起来对，
   策略却会被打穿。表现是：minimax 玩家在自对弈里没问题，一换对手就崩。
2. **吃行的挑选用 `min`/`max`，不吃行的那一步用矩阵博弈**，两者不能混。
3. **`own` 这个"视角"参数要贯穿到底**：对手挑行时用的是对手的价值函数，不是我方的。
   这个 bug 又一次出现了（和上一篇 §6 同一类），症状同样是"数字看着正常，自对弈不对称"。

复杂度：每个局面一次 `k×k` 矩阵博弈，`k ≤ 5`。

## 3. 结果

### 3.1 一副具体的牌

```
P1 手牌 [1, 4, 6, 9, 11]   P2 手牌 [2, 5, 7, 10, 12]  桌面 [[3], [8]]

博弈值 VM(开局) = +0.5924      （正数 = 双方都最优时 P1 平均少 0.59 分）
首手最优混合：1 号 25%、4 号 18%、9 号 1%、11 号 57%
耗时 1.5 秒；22484 个可达局面里，只有 1356 个（6%）需要解 LP，其余 94% 有纯策略鞍点
```

对局（精确枚举，不是采样）：

| 对局 | 我罚分 | 对手罚分 | 我 − 对手 | 我胜率 |
|---|---|---|---|---|
| 最优(vs随机) vs **随机** | 2.0333 | 9.0083 | −6.98 | **90.73%** |
| minimax vs **随机** | 3.4862 | 8.7031 | −5.22 | 80.92% |
| 最优(vs随机) vs **minimax** | 4.7940 | 3.8765 | +0.92 | 20.00% |
| minimax vs 最优(vs随机) | 5.1682 | 5.1014 | +0.07 | 34.04% |
| minimax vs minimax | 5.2300 | 4.6376 | +0.59 | 18.58% |

（最后一行那个 `+0.59` 必须等于博弈值——这是最硬的自检，实际完全相等。）

### 3.2 20 副牌平均

| 对局 | 我罚分 | 对手罚分 | 我 − 对手 | 我胜率 |
|---|---|---|---|---|
| 最优(vs随机) vs 随机 | 2.0312 | 10.0923 | **−8.06** | **91.20%** |
| minimax vs 随机 | 3.0351 | 9.5108 | −6.48 | 86.24% |
| 最优(vs随机) vs minimax | 5.3199 | 5.4082 | −0.09 | 44.26% |
| minimax vs 最优(vs随机) | 4.4640 | 6.4063 | −1.94 | 65.81% |
| minimax vs minimax | 4.9886 | 6.0604 | −1.07 | 49.80% |

（走 `minimax_small_game.py deals 20`，每副牌约 3 秒。）

两点关于这张表：

- **博弈值的平均严格是 0**（同一副牌换个座位，`VM(P1) = −VM(P2)`，逐副验证过；随机发牌下两个座位对称）。
  20 副的样本均值是 −1.07，这只是抽样波动——单副的 VM 能从 −7 摆到 +6。
- 表里所有「我 − 对手」都是从**行首那个策略使用者**的视角算的，换座位不是同一个对局。

### 3.3 那两行"看起来应该对称"的结果，为什么不对称

```
最优(vs随机) vs minimax   5.32 : 5.41   u = −0.09
minimax vs 最优(vs随机)   4.46 : 6.41   u = −1.94
```

很多人第一眼觉得这两行应该互为镜像。**不是**——它们不是同一局的两种视角：

| 行 | P1 拿 H1 打 | P2 拿 H2 打 |
|---|---|---|
| A | **π\*** | minimax |
| B | minimax | **π\*** |

两行里 π\* 都在打 minimax，但**它拿的手牌不同**（A 拿 H1，B 拿 H2）。这是两个不同的对局。

**真正的镜像关系**是「手牌对调 **且** 策略座位对调」：

```
C(d) = 在 (H2, H1) 上让 minimax 坐 P1、π* 坐 P2
```

对称性要求 `A(d)[π*] == C(d)[π*]` 且 `A(d)[mm] == C(d)[mm]`。实测 5 副牌，
**误差全部是 0.0e+00**（`minimax_small_game.py sym 5`）。所以实现没有座位偏置。

### 3.4 那 A 和 B 的平均该不该相等？

**该。** 发牌对两个座位是对称的：π\* 在 A 里拿 H1、在 B 里拿 H2，两个都是均匀随机的 5 张牌。
所以长期平均应该收敛到同一个数——但**单副牌可以差得很远**。

40 副实测：

| | π\* 的平均罚分 |
|---|---|
| 坐 P1（对手 minimax） | 5.6427 |
| 坐 P2（对手 minimax） | 5.7875 |

差 **−0.1448**，逐副差值的标准差 **3.57**，标准误 0.565，95% 置信区间 **[−1.25, +0.96]**（跨 0，不显著）。
而逐副差值能到 **+8.00 / −7.50**，说明单副牌的方差极大。

所以 20 副看到的 1.09 差距就是这么来的：**样本从 20 加到 40，差距从 1.09 缩到了 0.14。**

按 `SD ≈ 3.6` 估，要分辨多大的差异需要多少副牌：

| 想分辨 | 需要副数（95% CI 半宽 = 该值） |
|---|---|
| 1.0 分 | 约 50 副 |
| 0.5 分 | 约 200 副 |

⚠️ 注意这里的噪声**不是采样噪声**：每副牌都是**精确解**，一点蒙特卡洛都没打。
噪声全部来自**牌局本身**的随机性——只要你在随机牌局上取平均，就逃不掉。
这和完整版项目里那个「±2% 置信区间」是同一类问题。

## 4. 三个反直觉的发现

### 4.1 只有 6% 的局面真的需要混合

22,484 个可达局面里，94% 有纯策略鞍点——也就是说在这些局面上，"最坏情况最好"的那张牌是确定的，
根本不需要随机。只有 6% 的局面是真正"猜拳"的。

但这 6% 决定了整局：正是它们在阻止你被读牌。

### 4.2 「为最坏情况买保险」的代价比想象中小

对随机对手：最优(vs随机) 2.03 分 / 91.2% 胜率，minimax 3.04 分 / 86.2%。
**买保险只花了约 1 个罚分、5 个百分点胜率。** 这比我预期的小得多——因为 94% 的局面上两个策略本来就一致。

所以"要不要为强对手做准备"这个问题，在这个游戏里的答案是：**准备的成本很低，值得**。
这和完整版项目里"打随机刷到 95%"的处境形成对照：那里的 95% 是对一个很弱的对手定价的。

### 4.3 期望差和胜率是两个不同的最优

看这一副牌：minimax vs minimax，我平均只多 0.59 分（期望差是正的、对我略不利），
**但胜率只有 18.6%**。

原因是分布很不均匀。同一副牌上 minimax 打贪心的实际分布是这样的：

```
me=4 opp=3   p=0.433  输
me=5 opp=4   p=0.144  输
me=6 opp=4   p=0.127  输
me=4 opp=13  p=0.113  赢
me=6 opp=11  p=0.082  赢
me=4 opp=12  p=0.065  赢
```

**七成的时候我会窄输（4:3、5:4），三成的时候我会大赢（4:13、6:11）。**
平均下来我是赚的（−1.27），但按"赢的局数"算只有 29.5%。

这正好是第十二轮 `self` / `diff` 那个纠结的根源：**"少输一分"和"多赢一局"不是同一个目标**，
而且不存在一个策略能同时最优。minimax 优化的是 `u` 的**大小**，不是 `u` 的**符号**；
真要最大化胜率，得把分数差放进状态重新算一次 DP（`±19` 共 39 种，状态数 ×39），本文件没做。

## 5. 没做的：best response 与 exploitability

这里有个容易混的地方，值得单独说：

| 概念 | 在问什么 | 算法 |
|---|---|---|
| **minimax** | 面对**任何**对手，我至少能保证多少 | 每态解矩阵博弈 |
| **best response** | 面对**这个**对手，我最多能榨出多少 | 单智能体 DP（对手策略固定） |

两者是对偶的：minimax 保证自己不被榨干，best response 榨干别人。
**一个 minimax 策略不是"最强"的策略，它只是"最不容易被针对"的策略。**

这解释了 §3.2 里那个看起来奇怪的结果：20 副平均下，最优(vs随机) 打 minimax 基本打平（u = −0.09，
差不到 0.1 分）。**不是因为它稳健，而是因为 minimax 玩家根本不在乎针对它**——
它在保证自己的下界，不在最大化对你的优势。

要量「最优(vs随机) 到底有多容易被针对」，需要算 **best response to π\***：
对手知道 π\* 的每一条规则，直接选最狠的那张牌。那时 π\* 的期望差会明显变差。

这个 DP 没做（工作量不大，但和 minimax 是两套东西）。**所以本文件能说的是"π\* 不够稳健"，
不能说"π\* 会被打掉多少分"。**

## 6. 状态数不是瓶颈：为什么不用缩到 10 张牌

最初的想法是"10 张牌状态少 20 倍，应该更好算"。**实测下来这不是关键。**

| | 12 张牌 | 10 张牌 |
|---|---|---|
| 全量合法局面 | 21,827,586 | 1,133,970 |
| **一副牌的可达局面** | 22,484（实测） | 1,858（实测） |
| 每个局面要做的事 | 解一个 ≤5×5 矩阵博弈 | 解一个 ≤4×4 矩阵博弈 |
| 一副牌的耗时 | **1.5 秒** | 更快，但没必要 |

原因：真正决定成本的是**每个局面都要解一次矩阵博弈**，而可达局面本来就少（上一篇 §2.2 已经讲过）。
22,500 个局面 × 一次 LP，1.5 秒就完了。缩到 10 张牌只会让它更快，不会让它"从不能做变成能做"。

**能用 12 张牌，就继续用 12 张牌**——状态空间大 20 倍，但可达子图只大 10 倍，而且矩阵游戏没变大多少。

## 7. 五条能带走的

1. **同时出牌 ⇒ 矩阵博弈 ⇐ 混合策略。** `min_x max_y` 和 `max_a min_b` 是两个不同的东西，
   区别就是"我知不知道对手这一步出了什么"。
2. **零和化是一个建模选择。** `u = 我 − 对手` 回答"谁赢"，不回答"我少吃多少"。
   选错了收益函数，"最优"就是错的最优——§4.3 就是它的代价。
3. **确定性策略在完全信息 + 同时出牌里是可被读的。** 这就是为什么"打随机 95%"不能证明强。
4. **minimax ≠ 最强，= 最难被针对。** 想赢得多，要的是 best response；想输得少，要的是 minimax。
5. **先算瓶颈在哪。** 这次差点为了"状态数"把牌从 12 张缩到 10 张，
   而真正的瓶颈（每态矩阵博弈）缩牌数只解决了一点点。
6. **"两行不对称"先别当 bug。** 先问清它们是不是同一个对局、有没有配对；
   再拿恒等式（换座位必须同结果）验实现，最后才用置信区间判噪声。
   这次三步下来：恒等式误差 0.0e+00（没有偏置），40 副的差 −0.14 ± 0.57（噪声）。
