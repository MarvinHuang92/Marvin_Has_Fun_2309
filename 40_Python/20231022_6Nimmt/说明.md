# 6 Nimmt!（牛头牌）神经网络 AI（2023-10-22）

用 PyTorch 训练神经网络去玩桌游 **6 Nimmt!（牛头牌 / Take 5）** 的练习项目。

一句话概括：**游戏引擎自己写 → 对局中把 (局面, 动作, 得分) 录成训练样本 → 训练一个「局面+动作 → 预期罚分」的回归网络 → 打牌时枚举所有合法动作、取预测罚分最小的**。本质是**监督学习模仿一个手写启发式 AI**，不是强化学习。

## 游戏规则速查

- 牌堆 `1 ~ players×10+4`（2 人局 = 24 张），每人 10 张，桌面 4 行各 1 张起始牌。
- 10 回合，每回合所有人同时选一张牌，**按牌面从小到大**依次处理：
  - 比所有行尾都小 → 出牌者选一行吃下（该行清空，这张牌放到行首）；
  - 否则贴到「行尾比它小且差值最小」的那一行末尾；
  - 该行已满 5 张 → 出牌者吃下整行。
- 牛头数（罚分）越多越差：
  - `55` → 7 个
  - 尾数是 5 → 2 个
  - 10 的倍数 → 3 个
  - 11 的倍数 → 5 个
  - 其它 → 1 个
- 10 回合结束罚分最少者胜（并列时用「带噪声的牛头数」随机决定，见 `run_game()` 结尾）。

## 神经网络方案

### 样本结构（60 列）

`NNSampleData` 每个回合更新一组，`state + action + reward = 40 + 14 + 1 = 55`，v2 格式再追加 5 列元数据，共 60 列：

| 段 | 列 | 内容 |
|---|---|---|
| state 手牌 | 0~19 | 10 张手牌的（数字, 牛头），不足 10 张补 0 |
| state 行信息 | 20~35 | 4 行空位数(20~23) + 4 行行尾牌的（数字, 牛头）(24~31) + 4 行牛头总数(32~35) |
| state 其它 | 36~39 | 玩家数、剩余手牌数、当前罚分、决策类型（0=出牌 / 1=选一行吃下） |
| action | 40~53 | one-hot：`0~9` = 出第几张手牌，`10~13` = 吃第几行 |
| reward | 54 | 这一步的分数（默认是启发式**预期**罚分，可用 `reward_to_go.py` 换成别的标签） |
| 元数据 | 55~59 | `game_id`、`round`（1~10）、`seat`（1-based）、`penalty_this_round`（本回合**真实**罚分）、`score_before_round`（回合前累计罚分） |

> ⚠️ 启用额外特征（见下节 `extra_feature_mode`）时，这 E 列会插在 state 与 action 之间（第 40 列起），**后面所有列号整体后移 E 位**；`get_data()` 与 `reward_to_go.py` 都已按配置/行宽自适应。

元数据的用途：**一次采集，离线派生任意标签**。因为罚分只累加，`reward-to-go = 局末总分 − score_before_round`，不用重跑对局。

> 旧的 `02_nn_sample_data_full.csv` 只有前 55 列；`get_data()` 现在按 `line[input_col_max]` 取 reward，两种格式都能读。

### 网络输入为什么是 54

`x = state(40) + action(14)`，即 **Q(局面, 动作) → 预期罚分** 的回归网络（`neural_network_run.py` 里的 `input_col_max = 54`）。

出牌时把每个候选动作都拼一遍喂进网络（`Player.neuronNetworkCalc()`），**取输出最小的那个**；吃行时同理，在动作 10~13 里选最小的。

### reward 从哪来

默认**不是**真实回报，而是 `Player.advAiCalcPlayCardReward()` 这个手写启发式的估价：

- `safe`（安全牌）：0
- `smallest`（比所有行尾都小）：`min(各行牛头)`
- `danger`：`该行牛头 + 空位数 × (两张牌之间牛头数)/104`

样本由**随机出牌的玩家**对局产生（`simple_ai`）。所以网络学到的是「模仿这个启发式的估价函数」。

想看「真实回报」的版本，用 [reward_to_go.py](./reward_to_go.py) 从同一批数据离线重算，两种标签的效果对比见 [优化记录.md](./优化记录.md)。

### 训练设置（[neural_network_run.py](./neural_network_run.py)）

| 参数 | 值 | 说明 |
|---|---|---|
| `model_type` | `"fitting"` | 回归任务（`classification` 分支也在，但这份实验没用） |
| `task_type` | `"prediction"` | `training_new_model` / `training_existing_model` / `prediction` / `model_visualization` |
| `csv_input` | `game_log/02_nn_sample_data_full.csv` | 训练样本，三选一：旧 55 列数据（仓库自带）／`..._full_v2.csv`（含元数据）／`..._rtg.csv`（reward-to-go 标签） |
| `input_col_max` | `54 + extra_features` | = state(40) + 额外特征 + action 14，由 `extra_feature_mode` 自动推导 |
| `reward_col` | `54 + extra_features` | reward 所在列，默认紧跟 action；训练只吃 state 的 V(s) 时要单独指成 state 维度 + 1 附近的位置 |
| `extra_feature_mode` | `"none"` | 额外特征开关，见下节 |
| `normalize_state` | `False` | 是否把 state 各段除以其量纲压到 0~1（牌号/牌堆、牛头/7、空位/5、罚分/60…） |
| `batchsize_tr` / `training_batch` | 8000 / 4 | 4 组 × 8000 条 = 32000 条训练 |
| `batchsize_pr` / `sample_start_pr` | 1000 / 32000 | 「预测」集从第 32000 行开始 |
| `hidden_layers` / `n_hidden` | 1 / 12 | 改这里就是改网络结构 |
| `n_epochs` | 2001 | 梯度下降步数 |
| `learning_rate` | 5e-4 | 新建模型时自动 ×10；loss = MSELoss，优化器 Adam |

> 「模型参数.xlsx」里所有模型都是 `epoch=2001`、`8000 × 4 batch`、`lr=5e-4`、`relu` 训练出来的，只有隐藏层结构不同。

### 额外特征（`extra_feature_mode`）

| 值 | 维度 | 内容 |
|---|---|---|
| `"none"` | 0 | 不加，state 仍是 40 维 |
| `"row_segments"` | 4 | 用 4 个行尾牌把牌堆切成 4 段，每段「已出牌比例」（方案 A） |
| `"played_onehot"` | 24 | 每张牌是否已打出（2 人局 24 张牌，方案 F 对照组） |
| `"hand_bullheads"` | 3 | 其他人已累计罚分、自己手牌牛头总数、对手手牌牛头总数（第六轮） |
| `"teacher_scores"` | 14 | **把 advanced_ai 的估值公式当特征**：每个动作一个分数（第七轮，效果最好） |
| `"teacher_summary"` | 5 | 老师估值的聚合量：最小/均值/最优与次优之差/安全动作个数/最大（第七轮对照组） |

「已出牌」= 桌面 4 行上的牌 + 双方罚牌堆里的牌（都是公开信息）。
**训练、对局、评测三处的开关必须一致**，否则输入维度对不上。

第二轮的实测结论：在当前启发式标签下，这两种特征都没有提升（65.3% / 62.7% vs 基线 67.6%）；
第三轮换成优势标签 + 归一化后重测，4 维特征仍然没有提升（60.4% vs 60.8%）。
原因见 [优化记录.md](./优化记录.md) —— 简单说就是**标签不看这份信息**，而且数据里同一个局面只出现一个动作，反事实学不出来。

第六轮又加了 `hand_bullheads`（3 维：对手罚分 + 双方手牌牛头），同样没有可测提升（69.45% vs 69.80%）。
**规律：只要「老师/标签」不看这份信息，加特征就不会有用。**

### 为什么胜率「比较一般」

1. **天花板就是那个手写启发式**：标签是 `advAi` 的估价，网络最多模仿到它的水平，而且学不到「多回合策略」（比如故意留牌、卡别人）。
2. **训练状态分布不真实**：样本全部由随机玩家对局产生，网络没见过「高手对局」里的局面。
3. **特征太薄**：40 维状态里没有「已经打过哪些牌」「对手还剩几张」，只有行尾牌 → 判断不出别人手里大概有什么。
4. **单步估价，不是真实收益**：reward 是启发式估算，不是「这一手之后到局末的实际罚分差」。
5. **容量不是瓶颈**：参数量从 673 涨到 28001，胜率一直在 63%~68% 徘徊。

### 优化历程与结论（第一 ~ 十四轮，完整过程见 [优化记录.md](./优化记录.md)）

同一把尺子（vs 随机、固定种子、双方轮座）下的成绩阶梯：

| 阶段 | 做法 | 胜率 | 牛头占比 |
|---|---|---|---|
| 起点（2023 年的老代码） | Q 网络模仿单步估价 | 66.7% | ~40% |
| 第四~六轮 | 策略梯度 / 打分式架构 / 容量 120 | 69.8% | 36.7% |
| **第七轮** | 把老师估值当**特征** | **75.70%** | 32.79% |
| 第九轮 | （不学习）**纯搜索型玩家** | 92.70% | 16.55% |
| **第十轮** | **蒸馏搜索型玩家**（逐动作代价软标签） | **85.05%** | 25.01% |
| **第十一轮** | **网络剪枝 + 前 K 名 rollout**（`hybrid`） | **94.05% ~ 95.50%** | **15.29%** |
| 第十二~十四轮 | 各种旋钮（吃行搜索/提前停/混合先验/更多数据） | 95% 附近 | 15% 附近 |

**最有用的（实测收益）**：① 换一个更强的老师（搜索型，92.7%）→ 学生 +9.35 个点；
② 让"规划"参与决策（rollout）+17~28；③ 网络剪枝 + 搜索 +9；④ 好信息当特征 +6；
⑤ 软标签替代动作标签 +2，数据 2500 → 12500 局 +6（之后饱和）。

**没什么用甚至有害的（都是实测）**：自造特征（已出牌/行段/手牌牛头）0~−2；
换标签（reward-to-go **−10.8**、优势标签 −6、成对比较 −0.65）；残差结构 0；
归一化 0；KL 约束 RL 0；容量 120→400 只 +0.3；数据 12500→25000 只 +0.3；
吃行也搜索 +0.4；提前停只省 4% 时间；**把网络先验混进 rollout 代价 −1.5~−3.2**；
**偷看对手手牌 0**（→ 剩下的差距不是"缺信息"）；rollout 延续策略换随机只 −1.4。

**结论**：这个设定（24 张牌、10 回合、对手完全随机）下的实际天花板在 **95% 附近**，
再优化只能换评测口径（自对弈/真人）或换算法族（真正的 MCTS + 网络先验）。

### 改进方向（如果继续）

- **向前搜索/规划**（已实现，第九轮）：`search` 玩家对随机 92.70%、对老师 81.10%；
- **蒸馏搜索型玩家**（已实现，第十轮）：软标签学生 85.05%，比模仿手写启发式的 75.70% 高 9 个点；
- **网络剪枝 + 搜索**（已实现，第十一轮）：`hybrid` 94.05%~95.50%，比纯搜索更强且更省；
- 还没做的：自对弈迭代、MCTS（树内用网络先验而非均匀采样）、让网络输出"代价分布"以支持
  按置信度分配预算。

## 注意 / 已知坑

1. **必须在 `20231022_6Nimmt` 目录下运行**（相对路径 + `sys.path`）。
2. **模型是整对象 pickle**：加载时 `torch.load` 需要能 import 到 `neural_network_template`（在 `../202308_Neural_Network/`），所以那个目录不能删、不能改名。
3. 新版 torch（≥2.6）`torch.load` 默认 `weights_only=True`，加载整模型会失败；`load_model()` 里已显式写 `weights_only=False`（老版本 torch 没有这个参数，会走 fallback）。
4. `autoplay.py` 会**清空 `game_log\autoplay\` 旧日志**并往 `02_nn_sample_data_full_v2.csv` **追加**样本。
5. **`calcSampleRange()` 读的是模块全局 `task_type`，不是 `main()` 的入参**：配置里 `task_type = "prediction"` 时，"训练"批次实际取的是预测区间的切片（1000 条而不是 8000 条）；想按 `batchsize_tr` 训练，必须把全局 `task_type` 改成 `training_*`。这也意味着**训练集/验证集其实没真正分开**。
6. `model_type = "fitting"` 时训练日志里的 `accuracy` 是无意义的数字（`softmax_epoch()` 对回归任务也做了 argmax），看 `loss` 即可。
   另外它原来写的是 `y_pred.argmax(1) == y`，拟合任务下 `y` 是 `(N,1)` 会广播成 `N×N`，**让每步慢 17 倍**（150 秒 → 11.8 秒）；已在 `neural_network_template.py` 里改成 `y.view(-1)`。
7. `run_game()` 里玩家对象和 `CardDeck` 是用 `exec/eval` 动态创建的；牌堆只发 `players×10+4` 张，玩家数 >2 时规则是「缩水版」。
8. `Player.chooseCardToPlay()` 里 `simple_ai` 用 `random.randint(0, game.left_round)` 取下标 —— 依赖「手牌数 = 剩余回合数 + 1」这个巧合，改规则时要小心。
9. 做对比实验时注意 `game_log` 会被写入（追加样本、删旧日志），最好先备份再跑。
