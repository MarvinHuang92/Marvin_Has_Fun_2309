# 搜索端调参（2026-11-21）

> 模型那边已经三次撞墙（参数量、价值头、标签精度/容量），这次换到搜索端：
> **Lv3 的搜索还有没有空间？**

## 1. 方法

用 `mp_validate.py` 做**配对比较**：A、B 两套搜索参数同桌上场（5 人局：
人类代打 + 启发式 + A + B + 随机），座位逐局轮换 —— 同一副牌、同一批对手，
所以配对差的标准误只有 ±0.6~0.8（800 局）。

为此把原本的全局变量改成了**按座位生效**（默认值不变，不影响旧行为）：
`hybrid_k`、`search_criterion`、`opp_teacher`、`screen_m`。

## 2. 八个实验

| # | 实验 | A | B | 配对差 (A−B) | 判定 |
|---|---|---|---|---|---|
| 1 | 候选数 K | 3 | 6 | +0.51 ±0.75 | 打平 |
| 2 | 准则：diff vs max | diff | max | −0.57 ±0.76 | 打平 |
| 3 | 准则：diff vs self | diff | self | +0.30 ±0.77 | 打平 |
| 4 | rollout 次数 M（1400 局） | 24 | 48 | +0.37 ±0.50 | 打平 |
| 5 | rollout 里的对手策略 | 随机 | 老师 | −0.07 ±0.77 | 打平 |
| 6 | **控制变量：M** | **8** | **24** | **+1.57 ±0.69** | **M=24 明显更好** |
| 7 | 预算分配 K=3/M=24 vs K=10/M=8 | 72 次 | 80 次 | −1.80 ±0.66 | 是 M 的功劳，不是 K |
| 8 | 两阶段搜索（先粗筛 10 张 M=2，再深算前 3） | 关闭 | 开启 | −0.13 ±0.64 | 打平 |

## 3. 一个差点看错的结论

实验 7 第一眼很漂亮：**"少而深"明显赢"多而浅"（−1.80）**。
但那个对比同时改了 K 和 M —— 实验 6 一做控制变量就明白了：
**M=8 本身就值 1.57 分**，所以实验 7 的差距几乎全部来自 M，跟 K 没关系。

这就是配对实验里最容易踩的坑：一次只改一个变量，否则会把 A 的功劳记到 B 头上。

## 4. 结论：搜索端也到顶了

1. **M 是唯一有意义的旋钮**，而且存在明确的拐点：
   - 8 → 24：**+1.57 分**（很显著）
   - 24 → 48：+0.37（不显著，饱和）
   当前 GUI 的 `HYBRID_ROLLOUTS = 24` 正好在拐点上。
2. **其余全部打平**（|配对差| < 0.6，都在区间内）：
   候选数 K（3~6）、评价准则（diff / max / self）、rollout 里的对手策略（随机 / 老师）、
   两阶段粗筛。
3. 换个说法：**搜索"有"和"没有"值 2~3 分**（Lv3 ≈ 7.0 vs Lv2 ≈ 8.9~9.5），
   **搜索"怎么调"值不到 0.6 分**。

## 5. 所以这个项目到哪一步了

| 方向 | 结论 |
|---|---|
| 网络容量（673 → 28001 参数） | 无提升 |
| 价值头 / 截断 rollout（L1） | 反而更差 |
| 标签精度 M=12→48 + 容量 120→400 | +0.31，不显著 |
| **多人局数据**（2 人 → 2/3/5/7/10 混合） | **+3~5 分，唯一有效的改动** |
| 搜索端调参（8 个实验） | 全部 < 0.6 分 |
| GPU | 小模型上更慢 |

**结论：这套方法的收益已经被榨干了。** 剩下的差距不是"没调好"，而是方法本身的天花板
（单步估值 + 随机对手模型 ≠ 多回合博弈）。

## 6. 新增的可调开关（默认全关，行为不变）

| 属性 / 环境变量 | 作用 |
|---|---|
| `Player.rollout_count` / `SEARCH_ROLLOUTS` | 每候选的 rollout 次数（默认 12，GUI 用 24） |
| `Player.hybrid_k` / `HYBRID_TOP_K` | 网络剪枝留几个候选（默认 3） |
| `Player.search_criterion` / `SEARCH_CRITERION` | diff / max / self |
| `Player.opp_teacher` / `ROLLOUT_OPP=teacher` | rollout 里对手是否按老师规则出牌 |
| `Player.screen_m` / `HYBRID_SCREEN_M` | 两阶段搜索的粗筛次数（0 = 关闭） |

配合 `mp_validate.py` 的 `--a-*` / `--b-*` 参数，可以继续做配对消融：

```powershell
python mp_validate.py model_mix10k.pth model_mix10k.pth 800 --a-k 3 --b-k 6
python mp_validate.py model_mix10k.pth model_mix10k.pth 800 --a-m 24 --b-m 48
python mp_validate.py model_mix10k.pth model_mix10k.pth 800 --a-crit diff --b-crit max
python mp_validate.py model_mix10k.pth model_mix10k.pth 800 --b-screen 2
```
