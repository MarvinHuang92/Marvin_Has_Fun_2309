# L1：价值头截断 rollout —— 一次明确的负结果

> 目标（按上一轮的结论）：**同强度、省算力**。
> 做法：rollout 不再打到局末，只推 `depth` 个回合，剩下的用一个价值估计收尾。
> 结论：**算力确实省了（模拟回合数 4.5×↓），但墙钟反而变慢，强度掉 8 个点。**

## 1. 实现

AlphaZero 里最值得抄的一块不是树，是**价值头**：用 `V(s)` 在浅层截断，替掉那条又长又高方差
的随机尾巴。这个项目里正好有现成的价值来源：

```
V(s) ≈ min_a Q(s, a)
```

Q 就是打分网络预测的「逐动作代价」。关键在于它的**单位**：`sample_search` 采样时用的是
`SEARCH_CRITERION=diff`，所以 Q 预测的是 `我 − 对手` 的期望差——正好能直接接到
rollout 算到一半的 `me - op` 后面，不用换目标函数。

改动（`game_6nimmt.py`）：

| 新增 | 作用 |
|---|---|
| `HYBRID_DEPTH`（默认 0） | rollout 截断深度；0 = 不截断，和原来完全一样 |
| `Player.rolloutDepth()` | 决定这个座位截不截断；只有「带模型 + diff 准则 + teacher_scores 特征」才允许 |
| `simulatePartial()` | 和 `simulateRest` 一样，只是推 `depth` 个回合就停 |
| `Player.bootstrapValue()` | 把叶子局面拼成 68 维输入，取 `min_a Q` 当叶子值 |
| `teacherScoresFromRows()` | 从 rollout 的原始牌面重算 14 维老师特征（含分母 104、按 5 列算空位） |
| `ROLLOUT_STEPS` / `BOOTSTRAP_CALLS` | 算力计数，用来量化"省了多少" |

**正确性校验**：在 20 个真实局面上，`bootstrapValue` 的结果与 `scorePolicyScores`（现有的打分路径）
完全相等——说明特征拼法没写错，叶子值就是网络原本会给的值。

## 2. 结果（200 局，hybrid vs 随机，K=3 / M=24）

| depth | 耗时 | 模拟回合数 | bootstrap 次数 | 胜率 vs 随机 |
|---|---|---|---|---|
| **0（原版）** | **7.8s** | 813,354 | 0 | **94.0%** |
| 1 | 8.9s | **180,252** | 90,972 | 86.0% |
| 2 | 10.2s | 291,372 | 95,310 | 86.5% |
| 3 | 10.8s | 408,450 | 90,360 | 89.0% |
| 5 | 10.3s | 591,948 | 67,950 | 92.5% |

（200 局在 94% 附近的 95% 区间约 ±3.3%，所以 86% 对 94% 是实打实的差距。）

## 3. 两个都失败的地方

### 3.1 模拟省了 4.5 倍，墙钟反而慢了

depth=1 把模拟回合数从 81 万压到 18 万（**4.5×**），但总耗时从 7.8s 涨到 8.9s。

换算一下：

| 操作 | 单次耗时 |
|---|---|
| 一次 rollout 回合（`simulateRest` 里的一轮） | ≈ 9.6 µs |
| 一次 bootstrap（拼 680 个 float + 一次前向） | ≈ 79 µs |

**一次 bootstrap 抵得上 8 个模拟回合。** depth=1 只省了约 8 个回合、却加了一次 bootstrap——
刚好打平，再加上 Python 拼 list 的开销，净亏。

这不是根本性的：如果把这个前向**批量化**（一次决策里 K×M 个叶子攒起来算一次），
单叶成本能降到 ~4 µs，depth=1 大约会比原版快 2.7 倍。但见下一条。

### 3.2 强度掉 8 个点，而且规律很清楚

86.0% → 86.5% → 89.0% → 92.5%，**截得越浅掉得越多，越接近原版越好**。
也就是说：**这条长尾巴里的信息，比 `min_a Q` 能提供的更多。**

两个原因：

1. **丢掉了对随机性的平均。** 完整 rollout 是在"对手随机出牌"上做期望；截断后只剩一个点估计。
2. **`min_a Q` 是乐观估计。** Q 是用搜索的逐动作代价蒸馏出来的——它隐含"之后也按最优打"。
   但 rollout 的延续策略是**老师规则**（74.5%），不是最优。拿"最优未来"的估值接"次优未来"的
   实际走法，叶子值系统性偏高，候选之间的排序就被带偏了。

## 4. 结论

**L1 不成立：既不省时间（未批量时），也不保强度（批量也一样）。**

更重要的是一条可以带走的判断：

> 这个项目里 rollout 的成本**不在尾巴长度上，而在 rollout 的条数上**。
> 5 回合的截断省下 80% 的模拟量，但强度掉了 8 个点；
> 而只要把 K 从 3 降到 1，成本立刻降 2/3——代价却是几乎打不过随机。

所以「用价值头缩短 rollout」这条 AlphaZero 的经典路线，在这里撞上的不是工程量，是
**价值函数的质量**：只要 `V` 比"完整 rollout 的期望"差，截断就一定掉强度。

## 5. 什么情况下这条路才可能成立

1. **训练一个真正的 V(s)**（而不是拿 `min_a Q` 凑合）。第三轮训过 `model_value.pth`，
   但它只有 40 维状态、没有 `teacher_scores` 特征，和现在的输入不兼容，得重训。
2. **批量化前向**：把一次决策里的所有叶子攒起来算一次，单叶成本能降一个数量级。
3. **浅截断 + 混合**：`cost = (1-α)·完整rollout + α·V`，α 小一点当方差缩减用，
   而不是当替代品。这更像"控制变量"，不是"缩短"。

这三条都是 L2/L3 的活，而且按第 1 条的前提，得先有一个不弱于 rollout 的 V。
