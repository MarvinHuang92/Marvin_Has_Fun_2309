# 第一轮优化（2026-11-18）：样本记账 + reward-to-go 标签

## 1. 起点：四条改进方向的关系

当时的四条方向：

1. 标签换成「自对弈的实际得分 / reward-to-go」
2. 状态里加入「已出牌集合」「对手剩余张数」等特征
3. 改用策略梯度直接优化「少吃牛头」
4. 训练数据用 `advanced_ai` 或更好的策略生成（自对弈迭代）

**它们不是一条递进链**，真实关系是「一块地基 + 一个循环 + 两个可替换分支」：

```
                    ┌── 特征工程 (2)
                    │   正交、便宜、和算法无关
                    │
  地基 ─────────────┴── 记账：真实罚分 + reward-to-go  ← 无论走哪条路都要
                            │
              ┌─────────────┴─────────────┐
              │                           │
      Q 回归 (1)                     策略梯度 (3)
   state+action → 预测罚分        state → 动作概率
   取 argmin                      采样 + 基线
   （贴近现状，改标签即可）        （另一个算法家族）
              │                           │
              └──────── 自对弈 (4) ───────┘
                     数据引擎：训练 → rollout → 再训练
```

| 关系 | 说明 |
|---|---|
| (2) 是地基 | 网络唯一能「看见」的东西，不依赖也不阻塞其它三条，但所有算法都吃它的收益 |
| (1)(4) 不是先后，是绑定 | 永远在拟合 `Q^π`，`π` 是**生成数据的策略**。只换标签不换数据 = 学「随机对手世界里的最优」；只换数据不换标签 = 继续模仿有偏的启发式 |
| (3) 是 (1) 的替代 | 策略梯度不需要 `Q(s,a)`，和 (1) 只共用同一块地基（reward-to-go 的记账），不是「更高级的下一步」 |
| (4) 是外层循环 | 把一次性监督变成「训练 → 用新模型打 → 拿新数据 → 再训练」，套在 (1) 或 (3) 外面 |

执行顺序（按「便宜且能验证假设」排）：

| 顺序 | 做什么 | 成本 |
|---|---|---|
| 0 | 固定评测协议（同批种子、≥1000 局、对标 advanced_ai 的 73%） | 小 |
| **0.5** | **样本表加 `game_id` / `round` 等元数据，让标签可离线重算** | **小** |
| **1** | **记真实罚分 → 离线重算 reward-to-go，保持网络结构只换标签** | **小** |
| 2 | 加特征（已出牌集合、对手剩余张数） | 中 |
| 3 | 自对弈迭代 | 大 |
| 4 | 策略梯度 | 大 |

本轮只做 **0.5 + 1**，目的很明确：**用最小改动验证「短视的标签是不是主要瓶颈」**。

## 2. 本轮改了什么

### 2.1 两个标签概念先分清

| 概念 | 公式 | 在 6 Nimmt 里的值 | 学到什么 |
|---|---|---|---|
| 单步实际得分 | `r_t` | 本回合真实吃到的牛头（0~26） | `r(s,a)`，直接 argmin 会短视 |
| reward-to-go | `G_t = r_t + r_{t+1} + … + r_T` | 从本回合到局末累计罚分（0~60+） | `Q^π(s,a)`，argmin 才是正解 |

因为罚分只累加，**`G_t` = 局末总分 − 本回合开始前的累计分**，不用真的倒着求和。

### 2.2 样本表加元数据（第 0.5 步）

`NNSampleData` 在原来 55 列之后追加 5 列（总 60 列）：

| 列 | 含义 |
|---|---|
| 55 | `game_id`：对局编号（进程启动时间 + 序号，如 `20261118020305-1`） |
| 56 | `round`：第几回合（1~10） |
| 57 | `seat`：玩家序号（1-based） |
| 58 | `penalty_this_round`：本回合**真实**吃到的牛头 |
| 59 | `score_before_round`：本回合开始前的累计牛头 |

**关键设计：原来第 54 列（启发式 reward）保持不动**。于是一次对局采集的数据，可以离线派生任意多种标签做对比实验，不用重跑对局。

配套改动：

- 新增 [reward_to_go.py](./reward_to_go.py)，离线重算标签，原文件不动：
  ```
  python reward_to_go.py            # rtg（默认，γ=1）
  python reward_to_go.py step       # 单步实际罚分
  python reward_to_go.py rtg 0.9    # 带折扣的 rtg
  ```
- 样本总表改名为 `game_log/02_nn_sample_data_full_v2.csv`（v2 格式，gitignore 忽略）；旧的 `02_nn_sample_data_full.csv` 保留为历史数据（只有启发式标签、无元数据）。
- `neural_network_6nimmt.get_data()` 取 reward 的列从 `line[-1]` 改成 `line[input_col_max]`，同时兼容新旧两种格式。

## 3. 实验设置

**数据**：2500 局「随机 vs 随机」自对弈 → 59,814 行样本、5,000 条玩家轨迹。

**标签统计**（这组数字本身就说明了问题）：

| 标签 | 非零占比 | 均值 |
|---|---|---|
| 启发式（原标签） | — | ~1.5 |
| `step`（单步实际罚分） | **35.68%** | 1.4761 |
| `rtg`（reward-to-go） | **80.55%** | 7.2539 |

单步实际罚分有 2/3 的样本是 0（这一回合没人吃牌），等于「大部分样本告诉网络：这里没什么好学的」。

**正确性校验**：`rtg` 下「第一回合的 G」应严格等于「本局最终牛头数」，5000 条轨迹 **0 条不符**。

**训练**：三个模型完全同构同参（54 → 30 → 1，ReLU，Adam，MSE，2001 步 × 4 组 × 8000 样本，新模型 lr=5e-3、续训 5e-4），单次训练约 150 秒。

---

## 4. 结果（各 1000 局，网络作 P1 vs 随机电脑）

| 模型 | 训练数据 | 标签 | 牛头占比 | 胜率 |
|---|---|---|---|---|
| `model_30.pth`（旧模型，对照组） | 旧 CSV | 启发式 | 38.8% | **67.5%** |
| `model_heur_30.pth` | 新 v2 | 启发式 | 39.2% | **67.4%** |
| `model_rtg_30.pth` | 新 v2 | reward-to-go | 45.8% | **56.7%** |

训练 loss（MSE）：启发式标签 2.8~3.1；rtg 标签 18.4~20.1。

**换了 reward-to-go 之后，胜率反而掉了 10 个百分点。**

### 4.1 一个重要的旁证

`model_heur_30`（新数据 + 旧标签）和 `model_30`（旧数据 + 旧标签）胜率几乎相同（67.4% vs 67.5%），说明**这轮对样本格式和读取逻辑的改动没有引入回归**，对照组是可信的。

### 4.2 为什么变差了：网络几乎不区分动作

取 200 个「手牌满 10 张的出牌局面」，把 10 个候选动作分别喂给网络，看输出的极差：

| 模型 | 输出均值 \|Q\| | 动作间极差 | 极差/均值 |
|---|---|---|---|
| `model_heur_30` | 0.82 | 0.72 | **87.6%** |
| `model_30` | 0.71 | 0.59 | **83.5%** |
| `model_rtg_30` | 9.89 | 2.36 | **23.9%** |

rtg 模型学会了「这个局面大概还要吃多少分」（均值 ~9.9），但**对不同动作几乎给同一个分数**（极差只占 24%）。于是 `argmin` 基本等于在噪声里挑最小 → 表现接近随机（随机对随机的胜率约 50%，它 56.7%）。

原因（经典蒙特卡洛问题）：

1. **方差压倒信号**：`G_t` 里绝大部分波动来自「后面 5 回合摸到什么牌、对手怎么出错」，跟当前这一手关系很弱；MSE 从 2.8 涨到 18.4 就是这个方差的体现。
2. **没有基线**：`Q(s,a) = G_t`，网络先花容量去拟合 `V(s)`（局面本身好坏），剩下的 `A(s,a)`（动作差异）信噪比很低，30 个隐藏单元学不出来。
3. **数据仍是随机策略产生的**：想学的是 `Q^{π_随机}`，但对手/后续动作都是乱的，回报与「我这一手」的因果关系被稀释。

**结论**：不是「reward-to-go 这个方向错了」，而是**光换标签、不做降方差是不够的**。这正好把第一轮的地基打好了——现在可以离线对同一批数据做任意标签实验。

## 5. 下一轮计划（第二轮）

1. **降方差**（继续 1 的路线）：
   - `A(s,a) = G_t − V(s)`：先训一个只吃 state 的 `V(s)`，再用残差训练 Q；或
   - TD(0)：`Q(s,a) ← r_t + γ·V(s_{t+1})`，把长序列方差截断。
2. **加特征（第 2 步）**：已出牌集合（可用行分段计数压到 4 维 + 已出牌 min/max 等）、对手剩余张数；顺便把 state 里「牌号 0~104 / 牛头 0~7 / 人数 2」的混合尺度做归一化。
3. **自对弈**：用当前网络生成数据，替换「随机 vs 随机」，让数据分布跟上策略（要保留 ε-随机或启发式陪练防坍缩）。
4. 评测协议固化成脚本（同批种子、双方轮流坐庄）。

## 6. 本轮踩到的坑（备忘）

1. `calcSampleRange()` 读的是模块全局 `task_type`，**不是** `main()` 的入参 —— 所以配置里 `task_type = "prediction"` 时，训练批次实际取的是「预测区间」的切片；要按 `batchsize_tr = 8000` 训练，必须改全局 `task_type = "training_new_model"`。也意味着**训练集/验证集其实没真正分开**（同一切片既训又算 MSE）。
2. `str(list)` 写 CSV 会给字符串元素加单引号（`'20261118020305-1'`），写入时用 `.replace("'", "")` 去掉。
3. 标签尺度从 0~5 变成 0~60，学习率和 loss 的可比性直接失效；跨标签对比时要注意这一点。
4. 生成数据/评测会往 `game_log` 追加样本，做对比实验时要先把 `game_log` 挪走、跑完再还原，避免污染训练集。

# 第二轮优化（2026-11-18）：把「已出牌集合」加进 state（方案 A + 对照组）

> 第一轮的计划里把「降方差」排在前面，这里先做特征：改动更小、不用新造标签，顺便把「压缩到 4 维会丢多少」这个问题一次性回答掉。

## 1. 为什么想加这个特征

2 人局 24 张牌全部发出（2×10 手牌 + 4 张底牌），所以「已出牌集合」+「我的手牌」就能推出**对手手里可能有什么**。
注意这**不是隐藏信息**：已出牌 = 桌面 4 行上的牌 + 双方罚牌堆里的牌，玩家都能看见，只是现有 40 维 state 里没有编码它。

## 2. 压缩方案：4~8 维怎么压

原则不是「尽量无损压缩」，而是「**压缩成与决策直接相关的量**」。

| 方案 | 维度 | 做法 | 优点 | 缺点 |
|---|---|---|---|---|
| **A. 行分段计数** | 4 | 用 4 个行尾牌把牌堆切成 4 段，每段统计「已出牌比例」 | 和「这张牌会落到哪一行」直接对应，最贴合决策 | 段内具体分布丢失 |
| B. 均分桶计数 | 4~8 | 把 `1~N` 均分成 k 段，每段已出比例 | 实现最简单 | 桶边界与牌局结构无关：同样 0.5 的一段，可能对着满行也可能对着空行 |
| C. 统计矩 / 跨度 | 3~4 | 已出牌的 `min`/`max`/均值、最长连续未出空档 | 表达「牌堆还剩哪一大片没动过」 | 位置信息粗糙 |
| D. 投影到手牌 | 2~3 | 手牌被「已出牌」夹住的比例、到最近已出牌的平均距离 | 维度最省 | 丢信息最多 |
| E. 学习式压缩 | 4~8 | 把 N 维 one-hot 接一层 `Linear(N, 4~8)` 再拼进 state | 无损输入、自适应 | 吃数据、吃容量，可解释性差 |
| **F. 不压缩（对照）** | N | 每张牌一位 one-hot | 信息无损 | 维度高（2 人局 24 维，10 人局 104 维） |

方案 A 的具体定义：

```
把 4 个行尾牌排序（行尾牌本身不按行号递增！），得到 e1<e2<e3<e4
段 i = (e_i, e_{i+1}]，最后一段 = (e4, 牌堆最大牌]
落在段 i 的牌，按规则一定会贴到「行尾 e_i」那一行
特征 i = 段 i 内已出牌数 / 段 i 牌数        （归一到 0~1）
```

它和现有的「每行空位数」相关但不冗余：空位只说「这一行现在还能放几张」，段计数还包括**已经被吃掉的牌**，那才是判断「这一段还能撑多久」的关键。

本轮实现的是 **A（4 维）**，对照组取 **F（24 维 one-hot）**，用来回答「压到 4 维到底丢了多少」。

## 3. 实现

- `Game` 新增 `played_cards`（开局 4 张底牌 + 每回合 `arrangeCard()` 里打出的每张牌）和 `deck_size`。
- `Player.calcExtraFeatures()` 按配置给出额外特征，追加在 40 维 state 的「场景位」之后、14 维 action 之前。
- `neural_network_run.py` 新增 `extra_feature_mode`（`none` / `row_segments` / `played_onehot`），`input_col_max` 由它自动推导，避免维度和数据对不上。
- `reward_to_go.py` 改成按行宽反推列号，任何特征配置下都能用。

## 4. 实验设置

三个模型完全同构同参（隐藏层 30，2001 步 × 4 组 × 8000 样本，Adam + MSE；新模型 lr=5e-3、续训 5e-4），
**标签统一用启发式 reward**（第一轮已证明 rtg 单独用不行），只有输入特征不同：

| 模型 | 输入维度 | 额外特征 | 训练数据 |
|---|---|---|---|
| `model_heur_30` | 54 | 无 | 2500 局随机对局 |
| `model_rs_30` | 58 | 4 维行分段（方案 A） | 2500 局随机对局 |
| `model_oh_30` | 78 | 24 维已出牌 one-hot（方案 F） | 2500 局随机对局 |

三份数据由同一套流程各跑 2500 局生成（约 5.98 万行），差异只有采样噪声。

## 5. 结果（各 1000 局，网络作 P1 vs 随机电脑）

| 模型 | 额外特征 | 牛头占比 | 胜率 | 训练 MSE | **动作区分度**（输出极差/均值） |
|---|---|---|---|---|---|
| `model_heur_30` | 无 | **38.0%** | **67.6%** | 2.80 | **87.6%** |
| `model_rs_30` | 4 维（A） | 39.5% | 65.3% | 3.07 | **28.9%** |
| `model_oh_30` | 24 维（F） | 40.8% | 62.7% | 3.21 | **34.0%** |

「动作区分度」= 取 200 个局面、每个局面喂 10 个候选动作，输出的极差 / 均值绝对值。越高说明网络越会「区分动作」。

**两种特征都没有提升，反而略降；而且动作区分度断崖式下降（87.6% → 29%~34%）。**

## 6. 为什么没用：特征的价值取决于标签

关键发现：**现在的标签（`advAiCalcPlayCardReward` 的启发式估价）根本不用「已出牌集合」**。
它只读 `calcEachRowBlanks` / `calcEachRowLastCardValue` / `calcEachRowBullheads`，而「两牌之间有多少牛头」用的是固定不变的完整牌堆 `cardDeck.shadow`。

也就是说：

> 我在往输入里塞一个**标签根本不看**的信息。监督学习没有动机去用它；对拟合这个标签来说，它更像噪声。

于是网络把容量花在「用新增特征去拟合局面本身」，动作 one-hot 的相对权重反而被稀释 —— 这正好解释了「训练 MSE 没变差多少，但动作区分度掉了 2/3，胜率也掉」。

另外两个次要因素：

1. **输入尺度混杂**：牌号 1~104、牛头 0~7、空位 0~5、新特征是 0~1，第一层线性变换很难同时处理；新特征量级小，梯度贡献低。
2. **容量**：隐藏层只有 30 个单元，输入从 54 涨到 78 后，学「手牌位置 → 牌面」这类映射更吃力。

## 7. 结论与下一步

**结论**：加特征本身不是问题，问题是**配错了标签**。要让「已出牌集合」发挥价值，必须同时换成**真正依赖它的标签**（例如第一轮的 rtg，或自对弈/真实得分），并配合降方差。

下一步（第三轮）候选，按性价比排：

1. **rtg + 基线**：`A(s,a) = G_t − V(s)`（或用 TD(0) 自举），先解决第一轮暴露的「输出不随动作变化」；
2. **归一化整份 state**（牌号 / 牌堆大小等），再看特征是否仍无效；
3. 在 1+2 成立后，再复测方案 A（4 维）与方案 F（24 维），此时才有意义；
4. 容量对照：把隐藏层加到 60~120，排除「30 个单元不够」。

# 第三轮优化（2026-11-18）：基线降方差（A = G − V(s)）+ state 归一化

## 1. 本轮目标

接第二轮 §7 的第 1~2 点：

1. **降方差**：用 `A(s,a) = G_t − V(s)` 替代裸的 reward-to-go，看能不能修好第一轮暴露的「输出不随动作变化」；
2. **归一化**：把混合尺度的 state 压到 0~1 附近，再看第二轮的特征是否仍无效。

## 2. 做法

### 2.1 先训一个只吃 state 的价值网络 V(s)

直接复用现有框架，只是把输入改成「只取 state」（`input_col_max = state 维度`），
reward 列用新加的 `reward_col` 单独指定（因为此时 reward 不再紧跟 action）。

设置与 Q 完全一致：`state → 30 → 1`，2001 步 × 4 组 × 8000 样本，Adam + MSE，标签是 reward-to-go。

### 2.2 优势标签（[advantage_label.py](./advantage_label.py)，新增）

```
A(s, a) = G_t − V(s)
```

离线把 V(s) 在每条样本上算出来减掉，写回 reward 列。三个 V(s) 版本各自的标签统计：

| 数据集 | reward-to-go 标准差 | V(s) 预测标准差 | 优势标准差 | 降幅 |
|---|---|---|---|---|
| 无归一化 | 5.93 | 3.70 | 4.94 | 16.7% |
| 归一化 | 5.98 | 3.78 | 4.95 | 17.2% |
| 归一化 + 4 维特征 | 5.93 | 3.63 | 4.89 | 17.7% |

**注意：只降了 17%** —— V(s) 只能解释约 31% 的方差，剩下 69% 是「后面摸牌和对手的运气」。所以这一轮的降方差幅度有限。

### 2.3 state 归一化（新增开关 `normalize_state`）

在 `Player.getGameStateToNNData()` 里逐段除以各自量纲（保证「生成数据」和「对局推理」用的是同一套变换）：

| 段 | 原范围 | 除以 |
|---|---|---|
| 手牌 / 行尾牌的牌号 | 1~24 | 牌堆大小 |
| 牛头数 | 0~7 | 7 |
| 每行空位 | 0~5 | 5 |
| 每行牛头总数 | 0~35 | 35 |
| 玩家数 / 剩余手牌 | 2 / 0~10 | 10 |
| 当前罚分 | 0~60 | 60 |

## 3. 实验设置

沿用之前的一切（2500 局随机自对弈、4 组 × 8000 样本、2001 步、隐藏层 30），只改标签和输入处理：

| 模型 | 标签 | 归一化 | 额外特征 |
|---|---|---|---|
| `model_rtg_30`（第一轮） | rtg | 否 | 无 |
| `model_adv_30` | **优势 A** | 否 | 无 |
| `model_adv_norm_30` | **优势 A** | **是** | 无 |
| `model_adv_rs_norm_30` | **优势 A** | **是** | 4 维行分段 |

## 4. 结果（各 1000 局，网络作 P1 vs 随机电脑）

| 模型 | 牛头占比 | 胜率 | 训练 MSE | 动作区分度（绝对极差） | 极差 / 标签标准差 |
|---|---|---|---|---|---|
| `model_heur_30`（启发式标签，参考线） | 38.0% | **67.6%** | 2.80 | 1.68 | 0.80 |
| `model_rtg_30`（rtg，无基线） | 47.1% | 53.0% | 18.4 | 2.38 | **0.38** |
| `model_adv_30`（**+基线**） | 42.9% | **60.8%** | 17.3 | 3.68 | **0.76** |
| `model_adv_norm_30`（+基线+归一化） | 43.2% | 60.4% | 19.0 | 2.97 | 0.57 |
| `model_adv_rs_norm_30`（+基线+归一化+特征） | 44.2% | 60.4% | 19.9 | 3.65 | 0.66 |

（动作区分度：200 个出牌局面 × 10 个候选动作，输出的极差均值；「极差/标签标准差」= 区分度相对标签波动有多大。）

### 4.1 三个问题的答案

**Q1：基线有用吗？** 有用，但不彻底。
`rtg → adv`：胜率 53.0% → 60.8%，动作区分度相对量从 0.38 涨到 0.76（已经接近启发式模型的 0.80）。
**第一轮那个「输出几乎不随动作变化」的病治好了**，但仍比启发式模仿低 7 个百分点。

**Q2：归一化有用吗？** 没有可测的效果（60.8% → 60.4%，在噪声范围内）。
但要承认这个对比**不严格**：同一学习率下归一化会让首层梯度变小、收敛更慢（V(s) 的 MSE 从 19.0 变成 22.5），严格比要重调 lr。

**Q3：特征还有用吗？** 仍然没有（60.4% → 60.4%）。与第二轮的结论一致。

## 5. 关键结论：瓶颈不在标签，而在「反事实不可识别」

三轮下来可以确定一件事：**问题不是「用什么标签」，而是「数据里根本没有足够信息让你学标签」**。

- 数据是**随机玩家**打出来的，同一条轨迹里**每个局面只出现一个动作**；
- 而对手后续、摸牌顺序的随机性，让同一个局面的 `G_t` 天然有 ±5 的波动（正好是上表的标签标准差）；
- 于是「这个动作比那个动作好多少」的信号，被埋在比它大得多的噪声里 —— 模型只能学到「局面平均要亏多少」，学不到「动作之间的差异」；
- 启发式标签之所以能到 67.6%，是因为它是**确定性函数**：同一个局面下不同动作的标签本来就不同，模型可以学到自洽的估值（代价是天花板 = 老师）。

这解释了为什么「加特征」没用、为什么「换标签」只能到 60% 出头。

## 6. 下一步（第四轮）

1. **策略梯度（REINFORCE + 基线）**：只用实际动作的回报和 `G − V(s)` 当权重，**不需要反事实估计**；
   这一轮训好的 `model_value*.pth` 正好就是它的 baseline，等于已经做了一半。
2. **同一局面多动作分支采样**：对关键局面把每个候选动作都真的走一遍（分叉 rollout），直接造出反事实数据；代价是采样量成倍。
3. **自对弈**：数据分布跟上策略。
4. **固定评测种子集**（例如 2000 个固定种子、双方轮流坐庄），把评测噪声从 ±3% 压到 ±1%。

## 8. 本轮踩到的坑

1. **评测噪声比想象中大**：同一个 `model_rtg_30`，第一轮测 56.7%，这轮测 53.0%（都是 1000 局）→ 4 个百分点以内的差异不能当结论。
2. V(s) 训练时 reward 不再紧跟 action，`get_data()` 按 `input_col_max` 取 reward 会取错列 → 新增 `reward_col` 配置项。
3. 训练脚本里模型路径手写错（`model_adv_rs_30` vs `model_adv_rs_norm_30`），评测时才报 `FileNotFoundError`；模型文件里没有记录「特征模式 / 归一化」这些配置，**这类错只能靠命名约定避免**。
4. 归一化后在同一 lr 下收敛明显变慢（首层输入从 0~104 变成 0~1，梯度同比变小），跨配置比结果时要留意这一点。

## 附：要不要上 GPU（2026-11-18 实测）

### 1. 现状：这个 Python 环境用不了 GPU

| 项 | 实测值 |
|---|---|
| GPU | NVIDIA GeForce RTX 5070，driver 610.88，**compute_cap 12.0（sm_120 / Blackwell）** |
| 当前 torch | 2.4.1+**cpu**，`torch.version.cuda = None`，`cuda.is_available() = False` |
| Python 3.8 可装的 torch | **最高 2.4.1**（`pip index versions torch` 实测），2.5 起不再支持 3.8 |

RTX 5070 属于 sm_120，需要带 CUDA 12.8 的 torch（2.7 起才正式支持 Blackwell）。
所以要用 GPU **必须换解释器**（机器上已装 Python 3.13，或另建 3.11/3.12 虚拟环境）。

### 2. 但真正的瓶颈不是 CPU：一个广播 bug 吃掉了 94% 的时间

`softmax_epoch()` 里这一行：

```python
accuracy = (y_pred.argmax(1) == y).type(float32).sum().item() / len(y)
```

拟合任务下 `y` 是 `(N,1)`，而 `argmax(1)` 是 `(N,)` → 广播成 **N×N 的布尔矩阵**（N=8000 时是 6400 万个元素）。

| 每步耗时（8000×54，54→30→1） | 值 |
|---|---|
| 不计算 accuracy | 1.04 ms |
| 现在的写法（广播） | **17.96 ms** |
| 改成 `y.view(-1)` 后 | 0.96 ms |

改成 `y.view(-1)` 之后：**一个模型 4 组 × 2001 步，从约 150 秒降到 11.8 秒（12.7 倍）**，loss 轨迹不变（说明只去掉了无用的指标计算）。

### 3. 结论

**当前阶段不需要 GPU。** 理由：

1. 模型只有 **1681 个参数**、每批 8000×54 —— 这是 GPU 的「最差场景」，kernel 启动和同步开销占主导；
2. 修完上面的 bug 后，每步已 <1 ms，GPU 能带来的收益非常有限；
3. 而切 GPU 的成本是：换 Python + 下载约 2.9 GB 的 cu128 轮子 + 代码里加 `device`；
4. 数据生成和对局评测（纯 Python 模拟）**本来就用不上 GPU**，而那部分占了实验时间的一半。

**什么时候再考虑 GPU**：自对弈 / 分支采样让数据量涨 10~100 倍，或者网络换成卷积/更大结构时。届时：

```powershell
# 用 Python 3.13 建一个独立 venv，装带 Blackwell 支持的 torch
pip install torch --index-url https://download.pytorch.org/whl/cu128
```

代码侧要加 `device`：`get_data()` 的 x/y `.to(device)`、`create_model()` 后 `.to(device)`、
`load_model()` 的 `map_location`，以及 `game_6nimmt.Player.neuronNetworkCalc()` 里拼出来的输入张量。
注意模型是**整个对象 pickle**，GPU 上存的模型在 CPU 上加载需要 `map_location`，建议统一「CPU 训练 + CPU 保存」。

# 第四轮优化（2026-11-18）：固定种子评测 + 策略梯度（REINFORCE + 基线）

## 1. 本轮目标

接第三轮 §6 的第 1、4 点：

1. **先把评测固定下来**（第 4 点）：同批种子、双方轮座，否则每轮 ±3% 的噪声会把结论全搅乱；
2. **策略梯度**（第 1 点）：不再回归反事实估值，只用实际动作的回报和基线——正好绕开第三轮定位出的根因。

## 2. 先修评测：[evaluate.py](./evaluate.py)

```
python evaluate.py [局数] [模型] [extra_feature_mode] [normalize] [玩家类型] [起始种子]
```

- **固定种子**（默认 900000 起）：同样的模型每次跑结果完全一致（实测两次都是 651/1000）；
- **双方轮座**：同一副牌让网络分别坐 P1 / P2，消除座位偏差；
- `record_to_file=False`：不写日志、不写训练样本，**不会污染数据集**；
- 1000 局只需 **5.7 秒**（以前要 25 秒）。

### 2.1 顺带把前几轮的模型重测了一遍（固定种子，1000 局）

| 模型 | 胜率 | 牛头占比 |
|---|---|---|
| `advanced_ai`（手写启发式） | 72.80% | 34.5% |
| `model_heur_30`（监督模仿） | 65.10% | 40.1% |
| `model_rs_30`（监督 + 4 维特征） | **67.80%** | 38.3% |
| `model_oh_30`（监督 + 24 维 one-hot） | 62.20% | 42.3% |
| `model_rtg_30`（rtg 标签） | 55.70% | 45.9% |
| `model_adv_30`（优势标签） | 59.60% | 43.4% |
| `model_adv_norm_30`（+归一化） | 61.30% | 42.7% |
| `model_adv_rs_norm_30`（+归一化+特征） | 57.60% | 44.7% |

**结论要修正**：第二轮说「4 维特征让胜率从 67.6% 掉到 65.3%」——在固定种子下它反而是最高的 67.8%。
1000 局时两个模型比较的 95% 置信区间约 **±4 个百分点**，所以**第二、三轮里 2~3 个点的差异全部在噪声内**，只有 rtg / adv 之间那种 5 个点以上的差距才是真的。

## 3. 策略网络（[policy_6nimmt.py](./policy_6nimmt.py)）

```
state(40) → Linear(30) → ReLU → Linear(14) → logits
```

- 动作空间与 Q 网络一致：`0~9` 出牌、`10~13` 吃行；
- **合法动作掩码**：出牌时只有前 `handCount` 张合法，吃行时只有 10~13 合法，非法动作 logits 压到 `-1e9`；
- 新玩家类型 `"policy"`：`game_6nimmt.policy_sample = True` 时按 softmax **采样**（产生训练数据），`False` 时取 **argmax**（评测）。

## 4. 训练流程（[train_policy.py](./train_policy.py)）

```
python train_policy.py distill <数据.csv> <监督模型.pth> <输出.pth> [epochs]   # ① 蒸馏热启动
python train_policy.py sample  <策略模型.pth> <局数> <输出.csv>                # ② 采样 on-policy 数据
python train_policy.py train   <优势标签.csv> <策略模型.pth> [epochs] [lr]     # ③ REINFORCE
```

### ① 蒸馏热启动

用第三轮最好的监督模型 `model_heur_30` 当老师：对每个局面枚举 10/4 个合法动作，取老师 Q 最小的那个作为标签，交叉熵训练策略网络。

| epochs | 与老师一致率 | 评测胜率 |
|---|---|---|
| 30 | 36.3% | — |
| 400 | **69.0%** | 64.40% |

（400 epochs 只要 4.7 秒；30 epochs 明显欠拟合。）

### ② 采样 on-policy 数据

策略固定坐 P1 打 2000 局 vs 随机电脑（8 秒），约 **2.4 万条策略决策**，
格式沿用 v2 样本表（state + 动作 one-hot + 元数据），再用 `reward_to_go.py` / `advantage_label.py` 换成优势标签 `A = G − V(s)`。

### ③ REINFORCE

$$\nabla J = \mathbb{E}\big[\nabla \log \pi(a|s)\cdot A(s,a)\big],\quad
\text{loss} = \text{mean}\big(\log \pi(a|s)\cdot A\big)$$

- 只用**实际做过的那一手**，不需要「每个动作都试一遍」；
- 基线 V(s) 用第三轮训好的 `model_value.pth`（与动作无关，所以不引入偏差），训练时再减一次 batch 均值；
- 8 epochs / lr 3e-4 / 3.5 秒一轮。

## 5. 结果

**选择集**（900000 起，迭代时用）与**留出集**（950000 起，最终报告用）各 1000 局：

| 模型 | 选择集胜率 | 留出集胜率 | 留出集牛头占比 |
|---|---|---|---|
| `advanced_ai`（手写启发式） | 72.80% | **74.50%** | 34.4% |
| `model_heur_30`（监督模仿） | 65.10% | 68.60% | 37.7% |
| `model_rs_30`（监督 + 4 维特征） | 67.80% | 66.30% | 38.8% |
| policy 蒸馏热启动（rl0） | 64.40% | 66.70% | 39.0% |
| **policy + REINFORCE 第 1 轮** | 66.80% | **69.50%** | 37.5% |
| **policy + REINFORCE 第 2 轮** | **69.60%** | 67.70% | 37.1% |
| **policy + REINFORCE 第 3 轮** | 68.20% | **70.50%** | 36.4% |
| policy + REINFORCE 第 4 轮 | 66.70% | — | — |
| 从第 2 轮再跑（4000 局，lr 1e-4，4 epochs） | 68.00% | — | — |

## 6. 结论

1. **策略梯度是本项目第一个真正越过「模仿天花板」的方法**：
   热启动 66.7%（留出集）→ 三轮 REINFORCE 分别 69.5% / 67.7% / 70.5%，
   **每一轮都高于热启动**，而这个热启动本身就是在模仿监督模型。
2. **为什么它有效**：它完全不需要反事实估计——只用「我这个动作实际带来多少罚分、比预期好多少」，
   正好绕开了第三轮定位的根因（数据里一个局面只有一个动作，反事实不可识别）。
   本质是在「高概率动作」附近做局部搜索，把策略往低罚分方向挪一点。
3. **迭代之间的差异仍在噪声内**（67.7%~70.5%）：1000 局的 95% 置信区间约 ±3~4 个百分点，
   所以只能说「RL 后比热启动好」，不能说「第 3 轮最好」。
4. **仍然打不过手写启发式**（74.5%）：`advanced_ai` 里有针对性的领域规则（比如「收牛头最少的那行」、
   「危险牌按区间期望估值」），而策略网络只有 40 维输入和 30 个隐藏单元。
5. **第二轮「特征无效」的结论要打问号**：固定种子下 `model_rs_30` 反而最高，
   说明当时的 2 个点差距是噪声。特征是否真有用，需要更多局数或配对比较才能定论。

## 7. 下一步（第五轮）

1. **加大评测规模**：3000~5000 局，或对同一批牌做**配对比较**（同一个种子上两个模型各走一步），方差能再降一半；
2. **策略梯度的常规稳定化**：熵正则（保持探索）、lr 衰减、每轮样本量加大到 8000 局；
3. **自对弈**：让策略同时坐两侧，或与 `advanced_ai` 陪练（比随机对手更有信息量）；
4. **从更强的老师蒸馏**：直接蒸馏 `advanced_ai`（74.5%），起点会高很多；
5. 用第四轮这套 `evaluate.py` 重新审视第二/三轮的每一个结论。

## 9. 本轮踩到的坑

1. **选择集和留出集必须分开**：rl2 在选择集上最好（69.6%），留出集上却是 rl3 最好（70.5%）。
   只按一个固定评测集挑模型，等于在挑噪声。
2. 蒸馏 30 epochs 远远不够（一致率只有 36%），400 epochs 才到 69%，而代价只有 4.7 秒。
3. `sample` 必须关掉 `PER_GAME_FILES`：否则 2000 局会在 `game_log/autoplay` 下生成 4000 个文件。
4. 评测必须 `record_to_file=False`，否则会往训练总表里追加样本，污染数据集。
5. **训练 loss 一直下降 ≠ 策略变好**：rl5 的 loss 比 rl2 更负，但胜率更低（68.0% vs 69.6%）。
   策略梯度的 loss 没有绝对意义，只能看评测。
6. `save_policy()` 一开始不像 `load_policy()` 那样做路径解析，导致训练结果被写到项目根目录、
   而 `models/` 里留下的是旧的拷贝。已统一：只写文件名时两边都落到 `models/` 下。
   （教训：**保存和读取的路径逻辑必须对称**，否则「跑通了但存错地方」很难发现。）

# 第五轮优化（2026-11-18）：换更强的老师、修架构、换陪练

## 1. 本轮顺序（按性价比）

1. **换更强的老师**：第四轮从「监督 Q 模型」蒸馏热启动只有 66.7%，而手写启发式 `advanced_ai` 有 74.3%，直接模仿它；
2. **修架构**：模仿失败暴露了策略网络的结构问题，改成「打分式策略」；
3. **换陪练**：用 `advanced_ai` 当对手采样，让数据出现在更难的局面上；
4. **把评测钉准**：2000 局，把第四轮的结论量化清楚。

## 2. 实验与结果

### A. 模仿 advanced_ai（新增 `imitate` 命令）

让 `advanced_ai` 打 2000 局并记录它的动作，再交叉熵训练策略网络：

| epochs | 与老师一致率 | 评测胜率（1000 局） |
|---|---|---|
| 300 | 54.5% | 66.0% |

一致率只有 54.5%（对比：模仿 Q 模型能到 69%），胜率也只有 66.0%。

**原因诊断（2026-11-18 补充实测，修正了初次的推断）**：

我一开始以为这是「14 个输出共享同一个隐藏层，网络必须自己学会把第 i 张手牌路由到第 i 个输出」。
补做诊断后，真实的失败方式更具体：

1. **网络塌成了「只输出前几个位置」**：取 2000 个「第 1 回合、手牌 10 张」的局面，
   网络有 **1989 次**选第 0 张手牌；logit 与「该位置手牌大小」的相关系数只有 **0.02** ——
   它根本没在看牌面，只是固定偏好前几个槽位。
2. **老师（`advanced_ai`）的标签本身就严重偏斜**：同样这批局面里，它自己也 **51%** 选第 0 张。
   原因是它的 `sorted(...)[0]` 是稳定排序，大量并列 `reward = 0`（安全牌）时永远取手里最靠前的那张 ——
   而手牌是发牌顺序（非人类玩家不排序），所以「第 0 张是安全牌」的概率 ≈ 一半。
3. 于是 **54.5% 的一致率 ≈ 多数类基线（51%）**：网络学到的是「位置边际分布」这个先验，不是「看牌决策」这个条件分布。

为什么会塌到先验：`logit_i = w_i · h(s)`，`h(s)` 是整局的 30 维摘要，10 张牌的值全被混在同一组单位里；
而且**位置是可交换的**（同样 10 张牌换个发牌顺序，正确动作就完全不同），
架构里没有任何东西告诉网络「输出 i 应该去读输入槽位 i」，再叠加标签偏斜，最省力的解就是输出先验。

`advanced_ai` 不受影响，因为它**不是「输出一个数」，而是对每张牌各自算一个分数**（循环变量显式给出「这是第几张」）——
这正是第五轮 B 节那个「打分式策略」（state + 动作 one-hot → 分数）的结构。

> 补充：真正会出现「最优和次优被平均」的写法，是把动作当成**连续标量回归**
> （输出一个 0~9 的实数再四舍五入）；本项目用的是 14 维 logits + 交叉熵，没有这个问题。

### A2. 架构对照实验：换成打分式架构再模仿一次

为验证「输出结构是原因之一」这个判断，新增 `imitate_score` 命令：
**同样的训练数据、同样的 30 个隐藏单元、同样随机初始化**，只把架构从「14 logits」换成「state + 动作 one-hot → 1 个分数」。

| 架构 | 一致率（全部决策） | 一致率（仅出牌） | 出牌位置分布 | 胜率（留出 2000 局） |
|---|---|---|---|---|
| 多数类基线（永远选出现最多的动作） | 39.71% | 51% | — | ~50% |
| `PolicyNetwork`（14 logits） | 54.50% | 50.52% | `{0: 15183, 1: 2975, 2: 1519, 3: 251, ...}` | 64.80% |
| **打分式**（state + one-hot → 分数） | **58.97%** | **54.34%** | `{0: 12932, 1: 4236, 2: 1992, 3: 519, ...}` | **66.55%** |

**结论**：

1. **架构假说得到部分验证**：打分式比 logits 版 **+4.5 个点一致率、+1.75 个点胜率**，
   位置分布也从「几乎全挤在 0」变得稍微分散 —— 说明「输出位置和输入槽位对不上」确实是原因之一。
2. **但它不是主因**：两种架构都仍然严重偏向「前排」（老师自己也一样偏），
   说明真正学不会的是**「逐张判断这张牌安不安全」这个核心计算**——
   也就是 `advanced_ai` 里 `calcBullheadsBetween` + 空位数比较那一套公式，40 维输入 + 30 个隐藏单元装不下。
3. 交叉验证：把同一个打分式架构直接加载已训好的 Q 模型，贪心行为与 Q 的 argmin 完全一致（67.80%），
   说明架构本身没问题，问题在「这个任务对它的容量/特征来说太难」。
4. 对主线的启示：这条「模仿 advanced_ai」的支线最好只到 **66.55%**，
   仍低于主线「模仿 Q 模型 + REINFORCE」的 **69.20%**（第五轮 §3 表）。

### B. 架构修正：打分式策略（新增 `scorepolicy` 玩家类型）

改成复用 Q 网络的架构——**输入 = state + 动作 one-hot，输出 1 个分数**，再把分数取负做 softmax：

```
logits(a) = -Q(s, a) / T        →  softmax  →  采样 / argmax
```

这样「第 i 个动作」的信息由输入 one-hot 直接给出，不需要网络自己路由。
用 `model_rs_30`（监督 Q 模型）当权重，贪心行为与 Q 的 argmin **完全一致**（67.80% / 65.10% 分别复现）。

但用它做 REINFORCE 微调，**结果反而是负的**：

| 配置 | 热启动 | RL 后 |
|---|---|---|
| T=1.0, lr 1e-4, 8 epochs | 67.80% | **63.70%** |
| T=0.5, lr 5e-5, 4 epochs | 67.80% | 65.40% |
| T=1.0, lr 3e-5, 4 epochs | 67.80% | 65.90% |

**原因**：`log_softmax(-Q/T)` 的梯度会整体改变分数之间的差值，而**贪心策略只由 argmin 决定，
是个不连续函数**——随机策略的期望回报可能变好，argmin 的排序却被改坏了。
对比第四轮那个「本来就是策略」的网络：它没有这个「分数尺度」问题，RL 才能稳定加 2~3 分。

### C. 换陪练：跟 advanced_ai 对练

从第四轮最好的 `rl3` 出发，让策略与 `advanced_ai` 采样 2000 局再训练：

| 配置 | 结果 |
|---|---|
| rl3 → 与 advanced_ai 对练（lr 2e-4，8 epochs，熵权重 0.01） | **59.0%** |

明显退化。原因有三：① 训练数据来自「打 advanced_ai」的局面，与评测环境（打随机电脑）错位；
② V(s) 基线是在随机对手数据上训的，在这些局面上偏得厉害；③ loss 掉到 -3.3、熵从 ~1.2 塌到 0.59，更新过猛。

### D. 从「模仿 advanced_ai」的策略出发做 REINFORCE（第四轮的配方）

| 迭代 | 胜率 |
|---|---|
| 热启动（模仿 advanced_ai） | 66.00% |
| 第 1 轮 | 61.70% |
| 第 2 轮 | **55.50%**（崩了） |

同样的配方在第四轮（从「模仿 Q 模型」出发）是 64.4 → 66.8 → 69.6，这里却一路崩。
**起点策略的"尖锐程度"很关键**：模仿 Q 模型的一致率 69%，输出更确定；模仿 advanced_ai 只有 54.5%，
分布更"糊"，RL 一推就散。

## 3. 把评测钉准：2000 局（留出种子集 950000，95% 置信区间约 ±2%）

| 方法 | 胜率 | 牛头占比 |
|---|---|---|
| `advanced_ai`（手写启发式） | **74.25%** | 34.2% |
| **策略 + REINFORCE 第 3 轮（rl3）** | **69.20%** | 36.98% |
| 策略 + REINFORCE 第 1 轮（rl1） | 68.80% | 37.59% |
| `model_heur_30`（监督模仿） | 67.60% | 38.12% |
| 策略 + REINFORCE 第 2 轮（rl2） | 67.45% | 38.11% |
| 策略（蒸馏热启动） | 66.25% | 38.76% |
| `model_rs_30`（监督 + 4 维特征） | 65.65% | 39.22% |
| 策略（模仿 advanced_ai） | 64.80% | 40.04% |

## 4. 结论

1. **REINFORCE 的增益是真实的、但很有限**：热启动 66.25% → 68.8~69.2%（+2.5~3.0 个点，超出 ±2% 噪声），
   但 rl1 / rl3 之间（68.8 vs 69.2）无法区分。
2. **仍然是手写启发式最强**（74.25%），差了 5 个点。领域规则的价值比我们目前的网络容量 + 特征工程更大。
3. **架构改对了、但用错了地方**：打分式策略在「作为价值函数」时很好（贪心等价于 Q），
   但用 REINFORCE 去微调它会破坏 argmin 排序——**不要用 RL 去动一个已经很尖锐的 Q 策略**。
4. **起点决定成败**：同样的 RL 配方，从「尖锐的」热启动出发能加 2~3 分，从「糊的」热启动出发会崩。
5. 这一轮四个想法里只验证了「评测规模提升」有用；其余三个都是负结果，但都定位到了明确原因。

## 5. 下一步（第六轮）

1. **保守更新**：在 RL 时加 KL 约束（相对热启动策略）或早停，避免把 argmin 改坏；
2. **自对弈**：策略 vs 策略（需要放开 `POLICY_SEAT` 过滤，两侧都学），数据分布最贴近真实对手；
3. **回到特征**：既然 4 维「行分段」在固定种子下有 67.8%（第二轮最高），
   用第五轮这套流程（固定种子 + 2000 局）重新做一次「有/无特征 × 2000 局」的对照；
4. **认真学习 `advanced_ai` 的规则**：它的「危险牌估值」公式本身就是很强的先验，
   可以考虑把它作为特征喂给网络（而不是只当标签）。

## 7. 本轮踩到的坑

1. `sample()` 里写死了 `mode="none"`：用 58 维（含 4 维特征）的模型采样时直接报
   `mat1 and mat2 shapes cannot be multiplied (10x54 and 58x12)` → 现在 `sample()` 支持 `mode / normalize / opponent` 参数。
2. `build_states_and_masks()` 里写死 `STATE_DIM = 40`，一加特征就错 → 改成从列宽反推。
3. `evaluate.py` 对 `scorepolicy` 没有关掉采样（模块默认 `policy_sample = True`），
   导致「评测」其实是在按概率采样，与 Q 的 argmin 差 0.3 个点 → 修好后两者完全一致。
   （教训：**评测路径要显式关闭随机性**，否则你在测一个和部署时不一样的东西。）
4. `game_6nimmt.py` 的命令行原来没法指定特征配置，用含 4 维特征的模型手动跑一局会直接维度报错
   → 新增第 6、7 个参数 `extra_feature_mode` / `normalize`。

# 第六轮优化（2026-11-18）：容量、KL 保守更新、罚分/牛头特征

## 1. 本轮目标（按约定顺序）

1. **加大容量**（30 → 120 → 400 隐藏单元），看模仿 advanced_ai 能不能学得更好；
2. 若提升不明显，试 **KL 约束的保守 RL**（以热启动策略为参考，惩罚偏离）；
3. 备选方向（人类玩家的直觉）：state 里加「双方罚分 + 双方手牌牛头」。

**目标函数的约定**：优化目标定为 **累计牛头最少**（而不是胜率）——实际玩这个游戏通常也是多回合累计罚分。

> 实现时发现：**「自己的罚分」原本就在 state 第 38 位**里了，所以真正新增的只有 3 维。

## 2. 实验结果

### 2.1 容量（打分式架构，模仿 advanced_ai，400 epochs）

| 隐藏单元 | 参数量 | 与老师一致率 | 胜率（留出 2000 局） |
|---|---|---|---|
| 30 | 2,111 | 58.97% | 66.55% |
| **120** | 6,721 | **66.35%** | **69.80%** |
| 400 | 22,401 | **81.90%** | 69.70% |

**容量是最有效的一次单项改进（+3.25 个点）**，但对齐到 120 单元后胜率就饱和了：
一致率从 66% 涨到 82%，胜率纹丝不动。

→ 多出来的 15 个百分点花在「复现老师的并列选择顺序」（大量并列 `reward=0` 的安全牌）上，
对实战没有意义。**「一致率」不是好的模型选择指标**。

### 2.2 KL 约束的保守 RL（从 120 单元模仿模型出发，2000 局 on-policy 数据）

损失：`mean(logπ(a|s)·A) − 熵权重·H + β·KL(π_θ‖π_ref)`，参考策略 = 训练开始时的模型。

| β | 末轮 KL | 胜率 |
|---|---|---|
| 0（无约束） | 0.118 | 69.75% |
| 0.5 | 0.072 | **69.90%** |
| 2.0 | 0.013 | 68.60% |
| 10.0 | 0.001 | 69.10% |

**KL 起到了「止崩」作用**：第五轮同样的 RL 配方（β 相当于 0、起点 67.8%）会掉到 63.7%，
这次 β=0 也有 69.75%（起点更好），加 KL 后全部稳定在 68.6~69.9%。
但**没有任何提升** —— 说明当前瓶颈不是「优化不稳定」，而是**信息/天花板**。

### 2.3 新特征：对手罚分 + 双方手牌牛头（3 维）

| 新特征 | 均值 | 范围 |
|---|---|---|
| 其他人已累计罚分 | 2.73 | 0 ~ 28 |
| 自己手牌牛头总数 | 8.34 | 0 ~ 24 |
| 对手手牌牛头总数 | 8.57 | 1 ~ 24 |

（第三项 = 牌堆总牛头 − 已打出牛头 − 自己手牌牛头，2 人局所有牌都发完，所以能精确算出。）

两条路线各测一次：

| 场景 | 无新特征 | 有新特征 |
|---|---|---|
| 模仿 advanced_ai（120 单元） | 69.80% | 69.45% |
| 模仿 + KL 约束 RL（β=0.5） | 69.90% | **70.45%** |

- **模仿路线上没用**：因为 `advanced_ai` 的公式根本不看这些信息（和第二轮"特征取决于标签"的教训完全一致）；
- **RL 路线上 +0.55 个点**，在 2000 局的噪声（±2%）之内，**不能算提升**。

## 3. 当前总排名（留出种子集 950000，2000 局，±2%）

| 方法 | 胜率 | 牛头占比 |
|---|---|---|
| `advanced_ai`（手写启发式） | **74.25%** | **34.16%** |
| 打分式模仿 120 单元 + 新特征 + KL RL | 70.45% | 36.95% |
| 打分式模仿 120 单元 + KL RL | 69.90% | ~36.7% |
| **打分式模仿 120 单元**（纯监督） | 69.80% | **36.69%** |
| 策略网络 + REINFORCE（第四轮 rl3） | 69.20% | 36.98% |
| 打分式模仿 400 单元 | 69.70% | — |

## 4. 结论

1. **容量是这一轮唯一的显著收益**（66.55% → 69.80%），其余两项都在噪声内。
2. **KL 保守更新的价值是「不退化」而不是「变强」**：它把 RL 从"会崩"变成"稳定但原地踏步"。
3. **新特征在两条路线上都没有可测收益**：
   模仿路线上老师不看这些信息；RL 路线上数据量（2000 局）不足以分辨 0.5 个点。
4. **目标函数的提醒（呼应本轮约定）**：胜率和牛头占比会分叉 ——
   `模仿120` 是 69.80% 胜率 / 36.69% 牛头，`+新特征+KL` 是 70.45% 胜率 / 36.95% 牛头。
   如果目标真是"累计牛头最少"，应该按 **牛头占比** 选模型（此时 `模仿120` 更好）。
5. 距离 `advanced_ai`（74.25% / 34.16%）还差 4~5 个点，这个差距目前靠"更大的网络 + RL"补不上。

## 5. 下一步（第七轮）

1. **加大评测规模**（4000~5000 局）或**配对比较**，才可能分辨 1 个百分点级别的差异；
2. 把 `advanced_ai` 的**估值公式当成特征**喂给网络（而不是只当标签）—— 这是目前唯一还没试过的"信息注入"；
3. **自对弈**（策略 vs 策略，放开 `POLICY_SEAT` 限制两侧都学）；
4. 若目标严格是"累计牛头"，可以把损失直接对着「整局累计罚分」做策略梯度（而不是每步优势），
   并且用**牛头占比**而不是胜率来选模型。

3. 新特征在「模仿」场景下天然无效 —— 只要老师不看它，学生就没有理由学它。

# 第七轮优化（2026-11-18）：把估值公式当**特征**（而不是标签）

## 1. 出发点

前六轮的共同瓶颈是「信息」：40 维 state 里没有足够的决策依据，网络只能学到老师的粗略近似。
这一轮把 `advanced_ai` 的**估值公式本身**当成输入特征 —— 注意是**特征**不是标签：

| 用法 | 后果 |
|---|---|
| 当标签（第二~六轮） | 天花板 ≈ 老师 |
| **当特征（本轮）** | 输入多几维，表达能力不降，原则上可以超过老师 |

## 2. 两个方案

| 方案 | 维度 | 内容 |
|---|---|---|
| **A. 逐动作分数** | 14 | 出牌时填 0~9（每张手牌一个估值），收行时填 10~13（每行牛头） |
| **B. 聚合量** | 5 | 最小值 / 均值 / 最好与次好之差 / 分数 ≤ 0 的个数 / 最大值 |

实现：`calcTeacherFeature()` 在每个决策点调用 `advAiCalcPlayCardReward` / `advAiCalcRowReward`
（`getGameStateToNNData` 因此多了一个 `cardDeck` 参数），把结果拼进 state。

## 3. 结果（打分式架构，120 隐藏单元，模仿 2000 局 advanced_ai 数据）

| 方案 | 与老师一致率 | 胜率（2000 局） | 牛头占比 |
|---|---|---|---|
| 无特征（第六轮最好） | 66.35% | 69.80% | 36.69% |
| **B. 聚合量（5 维）** | 69.07% | 72.55% | 35.68% |
| **A. 逐动作分数（14 维）** | **98.82%** | **75.50%** | **33.06%** |
| A + KL 约束 RL（β=0.5） | — | 75.05% | 33.15% |

### 3.1 加大评测规模后再确认（4000 局，±1.4%）

| 模型 | 胜率 | 牛头占比 |
|---|---|---|
| **方案 A（纯模仿）** | **75.70%** | **32.79%** |
| 方案 A + KL RL | 75.70% | 32.78% |
| `advanced_ai`（老师本人） | 74.65% | 33.74% |
| 上一代最强（第四轮 rl3） | 68.42% | 37.61% |

## 4. 结论

1. **「信息」确实是前六轮的主瓶颈**：把估值公式当特征，一次把胜率从 69.8% 拉到 **75.7%**，
   牛头占比从 36.7% 降到 **32.8%**（+6.9 个点胜率，−3.9 个点牛头）。
2. **没有「失去超过老师的机会」**：模型与老师一致率 98.8%，但剩下的 1.2% 分歧 + 对分数函数的平滑近似，
   让它在 4000 局里 **略好于老师**（75.70% vs 74.65%，牛头 32.79% vs 33.74%）。
   胜率差距 1.05 个点在 ±1.0% 的噪声边缘，**只能说"打平或略好"，还不能宣称稳定超过**。
3. **方案 A 明显强于方案 B**（75.70% vs 72.55%）：给"逐动作的完整排序"比给"几个聚合统计"有用得多——
   因为选择动作需要的是**相对排序**，聚合量把这个信息压掉了。
4. **RL 依然没有加成**（75.70% vs 75.70%）：起点已经等于老师，
   REINFORCE 的优势信号（±5 的回报波动）不足以指出"老师哪里错了"。
   要继续往上，需要的是**更细的信用分配**（例如按回合的 TD、或成对比较），而不是更多的 RL 轮数。
5. 这就是「**先把手写的先验喂进去，再让网络学修正**」的经典做法的一次验证。

## 5. 下一步（第八轮）

1. **残差结构显式化**：`score = α·t(s,a) + net(s,a)`，α 初始 1、输出层零初始化
   —— 让起点严格等于老师，网络只学"修正量"，比现在"把 t 当普通特征"更有针对性；
2. **成对比较（pairwise）目标**：只学「同一个局面里动作 a 比 b 好多少」，
   这正好匹配 argmin 的语义，也比回归整局回报的方差小；
3. **评测继续加大**（6000~8000 局）才能分辨 1 个点级别的改进；
4. 把「老师的分数 diff」作为额外特征（t_best − t_a），可能比原始分数更有效。

## 7. 本轮踩到的坑

1. `evaluate.py` 的位置参数已经到 6 个（局数/模型/特征模式/归一化/玩家类型/种子），
   很容易传错一位（我这次就把 `advanced_ai` 传到了"特征模式"上）→ 建议后续改成具名参数。
2. 老师的估值特征需要 `cardDeck`（因为 `calcBullheadsBetween` 要用完整牌堆），
   所以 `getGameStateToNNData()` 必须多接一个参数；行选择时传 None，走"每行牛头"分支。
3. 特征值量纲依然混杂（老师分数 0~5，state 里牌号 0~24），但这次没做归一化也能学起来 —— 
   说明"信息量"比"量纲整齐"更关键。

# 第八轮优化（2026-11-18）：显式残差结构 + 成对比较目标

## 1. 两个想法

| 想法 | 动机 |
|---|---|
| **显式残差**：`score = α·t + net(s,a)`，输出层零初始化 | 让起点**严格等于老师**，网络只学"老师哪里算错了"，而不是把 t 当普通特征重新学一遍 |
| **成对比较**：只要求"老师认为更好的动作得分更低" | 匹配 argmin 的语义（只要排序），比拟合分数绝对值更省 |

## 2. 结果（4000 局，留出种子集 950000）

| 模型 | 胜率 | 牛头占比 |
|---|---|---|
| 第七轮 `model_score_ts`（t 当普通特征，CE 模仿） | **75.70%** | **32.79%** |
| 成对比较（从 `model_score_ts` 出发，8 epochs） | 75.05% | 33.23% |
| 残差 + RL（β=0） | 73.97% | 33.82% |
| 残差 + RL（β=0.5） | 73.92% | 33.86% |
| `advanced_ai`（老师） | 74.65% | 33.74% |

## 3. 结论

1. **残差结构的起点验证成功**：零初始化后评测 **74.25% / 34.16%**，与老师在同一评测集上的成绩**完全一致**，
   说明"α=1、修正=0 ⇒ 策略=老师"这个设计成立（这是很干净的实现验证）。
2. **但 RL 依然没有带来提升**（73.97% / 73.92% vs 老师 74.65%）。
   而且末轮 **KL 只有 1e-5**、α 只从 1 变到 1.004 —— 策略几乎没动过，
   说明这不是"更新太猛把好策略推坏了"，而是**优势信号根本不足以指出"老师哪里错了"**。
   差的那 0.7 个点在噪声内，本质是"原地踏步"。
3. **成对比较和分类目标打平**（75.05% vs 75.70%，差 0.65 个点在噪声内）：
   两者都在拟合同一个老师排序，只是损失形状不同，没有产生质的差别。
4. 综合来看：**当"老师的分"已经作为特征喂进去之后，再加 RL / 换排序损失都无法超过它**。
   要真正超越，需要的是**老师没有的信息**（对手建模、长程规划、分支反事实），而不是更好的优化。

## 4. 一个值得记的坑（成对比较第一次写反了）

第一版 `train_pairwise` 里写了 `scores = -model(x)`（因为"越小越好"顺手加了负号），
于是 `diff_s = s_a - s_b` 变成了 `model_out_b - model_out_a`，
hinge loss 实际在**鼓励相反的顺序**——评测直接掉到 **68.58%**（比随机好不了多少）。
改成 `scores = model(x)` 后回到 75.05%。

> 教训：**排序类损失里"越大越好"还是"越小越好"必须三处一致**（数据标签、损失里的符号、推理时的 argmax/argmin）。
> 这次是"推理按分数小者优、损失里却取了反"，结果 loss 曲线看起来很正常（还在下降），只有评测能暴露。

## 5. 下一步（第九轮）

1. **引入老师没有的信息**：对手手牌建模（用已出牌 + 罚分牌推断）、长程规划（把"未来 2~3 回合会不会被迫吃牌"编码成特征）；
2. **分支反事实**：对关键局面把每个候选动作真的走一遍（分叉 rollout），拿真实的"动作间差值"当标签 ——
   这是唯一能提供"老师不知道的新知识"的渠道，代价是采样量成倍；
3. 若目标严格是「累计牛头最少」，可以参考第七轮的教训，把 `α` 也纳入"牛头占比"的调参目标。
