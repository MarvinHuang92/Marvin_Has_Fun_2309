# GPU 可行性（2026-11-21）

> 目的：不是"把训练搬到 GPU"，而是先量清楚**什么规模的负载才轮得到 GPU**，
> 以后遇到更大的问题心里有数。工具：`gpu_probe.py`。

## 0. 结论先说

1. **本机有两个 torch，都是 CPU 版**：3.8 是 `2.4.1+cpu`、3.13 是 `2.15.0+cpu`。
   GPU 是 RTX 5070（sm_120），**Python 3.8 最高只能装到 torch 2.4.1**，不支持 sm_120，
   所以要用 GPU 就必须切到 **3.13 + torch cu128**。
2. **就当前项目的负载而言，GPU 帮不上忙**：
   - 模型极小（H=30），训练一步只要 **0.73 ms**——GPU 一次 kernel 启动就把这点收益吃掉；
   - 真正占时间的是**纯 Python 的搜索/rollout**（Lv3 一个决策约 6.4 ms），GPU 碰不到；
   - 一次完整重训里训练只占约 **4%**（12500 局采样约 48 分钟 vs 学生训练约 2 分钟），
     就算训练快 10 倍，总时长也只从 50 分钟变 45 分钟。
3. **但迁移本身是通的**：torch 2.15(3.13) 能读 2.4(3.8) 存的整模型，反向也测通了。
   所以"GPU 训练 + CPU 对局"这条分工可行。

## 1. 环境事实

| | Python 3.8 | Python 3.13 |
|---|---|---|
| torch | 2.4.1+**cpu** | 2.15.0+**cpu** |
| CUDA | 无（且最高只能到 2.4.1） | 无（可装 cu128） |
| numpy / scipy | 1.24.4 / 无 | 2.2.4 / 1.18 |

GPU：`NVIDIA GeForce RTX 5070`，12 GB，compute capability **12.0（sm_120）**，驱动 610.88。


## 2. CPU 基线（这个项目的真实形状：68 → H → 1）

**训练一步（ms）**，MSE + Adam，20 线程：

| H | batch 256 | 2048 | 8000 |
|---|---|---|---|
| 30 | 0.52 | 0.59 | **0.73** |
| 120 | 0.41 | 0.85 | 1.19 |
| 400 | 0.73 | 0.86 | 2.73 |
| 1600 | 0.98 | 2.80 | 13.9 |
| 6400 | 1.64 | 15.4 | **76.1** |

**推理一次（ms）**——游戏里每次决策的 batch 是 ≤10：

| H | batch 10 | 1024 | 16384 |
|---|---|---|---|
| 30 | 0.021 | 0.084 | 0.169 |
| 400 | 0.020 | 0.120 | 2.08 |
| 6400 | 0.048 | 1.94 | 64.5 |

**搜索**：4 人局单次 rollout **88 µs**，Lv3 一个决策（3 候选 × 24 次）约 **6.4 ms**。
纯 CPU 单线程，GPU 完全用不上。

## 3. 交叉点在哪

从训练表看，CPU 在 **H ≤ 400 时一步不到 3 ms**，这正是 GPU 最吃亏的区间
（kernel 启动 + 主机/设备拷贝就是几十微秒到百微秒级）。

粗略的拐点在 **H ≈ 1000~2000、batch ≥ 2048**：那里 CPU 已经 3~15 ms/步，
GPU 才有肉可吃。到 **H=6400 / batch=8000（CPU 76 ms/步）**，GPU 预计能快
**10~50 倍**（上限受显存带宽而不是算力限制，准确值等 `gpu_probe.py` 的 GPU 列补上）。

当前项目 H=30~400，**离拐点还差 1~2 个数量级**。

## 4. 迁移要付出什么

- 换解释器到 3.13，项目里所有 `import torch` 的地方都要在 3.13 下验证一遍；
- `neural_network_template` 不在项目目录里，要靠 `sys.path.append('../202308_Neural_Network')`；
- **模型文件双向兼容已验证**：
  - 2.15(3.13) 读 2.4(3.8) 存的 `model_score_ts.pth` → `forward ok`；
  - 2.15(3.13) 存一份，2.4(3.8) 读 → `loaded ok`。
  所以可以"GPU 上训练、3.8 上对局"，不用一次性把整个项目迁过去。

## 5. 什么时候才真的值得上 GPU

1. **模型变宽**（H ≥ 1000）或换成 Transformer 之类的结构；
2. **搜索变成可向量化的形式**——现在不行：`simulateRestN` 是 Python 循环 + 随机 +
   可变长度的行结构，GPU 无法批量；
3. **数据规模上到百万级**（现在 6 万行、8 千步就收敛了）。

换句话说：**这个项目的瓶颈从来不是"算得慢"，是"采样贵 + 决策噪声大"**。
GPU 解决的是前者，而这个项目卡在后者。
