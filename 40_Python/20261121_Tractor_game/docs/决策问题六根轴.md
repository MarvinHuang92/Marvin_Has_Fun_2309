# 决策类问题的六根轴（附具体游戏对照）

> 整理自 2026-11-21 那次讨论的第三节。这张表回答的是一个很具体的问题：
> **同样是「打游戏 / 做决策」，为什么不同问题要用完全不同的方法？**
>
> 下面用本项目的 6 Nimmt 做对照列，可以直接看出它落在每根轴的哪个位置——
> 也就解释了为什么它最后选的是「网络剪枝 + rollout」，而不是 DQN、PPO 或 CFR。

## 六根轴

同样是"打游戏"，差别全在这六根轴上：

| 轴 | 取值 → 方法 | 本项目的 6 Nimmt |
|---|---|---|
| **可观测性** | 全观测 → MDP；部分观测 → POMDP（RNN 策略 / 信念状态 / ISMCTS / CFR） | 名义上是 POMDP，实际可完全推出 → 当 MDP 处理是对的（见文末补充） |
| **动作空间** | 小离散 → 值函数 + argmax（Q 学习 / DQN）；大离散或连续 → 策略梯度、actor-critic（PPO / SAC）；**合法动作可变 → action masking** | 14 个离散 + 掩码，做了 |
| **奖励密度 / 信用分配** | 稠密 → TD(0)；稀疏延迟 → MC、n-step、reward shaping、HER；整局一个标量 → 策略梯度、进化算法 | 每回合结算，偏稠密；但"这一手 vs 十回合后被迫吃牌"是长程依赖 |
| **对手** | 无 / 固定 → 单智能体（可搜索）；自适应 → self-play + minimax + MCTS | 固定随机 → 单智能体 |
| **模拟器** | 有 → model-based（rollout / MCTS / MPC）；无 → model-free | 有，而且是自己写的纯数值引擎，1000 局 57 秒 → 搜索的性价比极高 |
| **数据来源** | 在线交互 / 离线数据集（offline RL、行为克隆）/ 人类示范 | 离线为主，一直在离线造数据 |

## 具体游戏对照

| 游戏 | 真正的难点 | 主流解法 | 和本项目的游戏差在哪 |
|---|---|---|---|
| **6 Nimmt（本项目）** | 长程规划 > 单步估值；有模拟器、动作少、回合制 | rollout / MCTS + 网络先验剪枝 | — |
| **贪吃蛇** | 状态是网格、动作 4 个、奖励稠密、**无对手**、无长程依赖 | DQN（经典）；甚至可以 A* 接控制 | 无对手 + 网格状态 → 端到端值函数很合适 |
| **Flappy Bird** | **奖励极稀疏**（活着一分、撞死归零）、像素输入、实时 | DQN + 帧堆叠 + reward shaping；也能用简单规则 | 稀疏奖励是主要敌人，不是对手 |
| **赛车** | **连续控制** + 物理 + 不能撞 | PPO / SAC、MPC、模仿学习 | 动作连续 → 值函数 argmax 失效，必须用策略梯度 |
| **围棋 / 象棋** | 巨大分支、完美信息、零和、**对手会适应** | AlphaZero：MCTS + 双头网络 + 自对弈 | 真 PvP + 需要搜索 |
| **德州扑克** | 不完全信息 + 零和 | CFR 系 | 隐藏信息**真**不可推 → 信念必须显式建模 |

注意这张表给出的关键洞察：

> **贪吃蛇和 6 Nimmt 都被归为"PvE"，但方法完全不同。**
> 原因不是对手，而是「**能不能 rollout**」和「**奖励稀疏不稀疏**」。
> **能不能搜索，比是不是 PvE 重要一个量级。**

## 怎么用这张表

拿到一个新问题，六根轴从上往下过一遍，方法族基本就唯一了：

1. **可观测性**决定你是 MDP 还是 POMDP（要不要显式建模信念）；
2. **动作空间**决定值函数能不能 argmax（连续动作就必须策略梯度）；
3. **奖励密度**决定信用分配怎么做（稀疏就得 shaping / MC / HER）；
4. **对手**决定是单智能体还是博弈（会变才需要 self-play）；
5. **模拟器**决定"规划"是否可行——有模拟器时，**搜索往往比学习便宜**；
6. **数据来源**决定能否用离线方法（行为克隆 / offline RL）。

本项目在这六根轴上的位置，合起来指向的正是它最后做的事：
**有模拟器 + 小离散动作 + 固定对手** → 单智能体 + 模型基规划 + 网络先验剪枝。
而"对手"这根轴一旦改成"会适应"，第 4 条立刻变成 self-play + minimax，
评估口径也要从"平均胜率"换成"exploitability"。

## 补充（2026-11-21 晚，实测后修正）

原文说"名义上是 POMDP，实际可完全推出"，这在**2 人局严格成立**，多人局要打折：

- **2 人局**：24 张牌全部发完（10 自己 + 10 对手 + 4 桌面），而桌面 4 张和自己 10 张都是公开的，
  于是 `对手手牌 = 24 − 4 − 10`，**由公开信息唯一确定**。所谓"隐藏信息"信息量为 0，
  这也解释了当年"偷看对手手牌 0 收益"的诊断为什么注定测不出东西。
- **N 人局**：牌仍然全部发完，但 `N−1` 家手牌只有**总和**能确定
  （`104 − 4 − 10 = 90` 张分给 9 家），**怎么分**是不知道的。
  所以多人局是**真的 POMDP**，`simulateRestN` 里"从未见过的牌里随机采 N−1 份手牌"
  是一个**采样的信念**，而不是完美信息。

这个区别有实际后果：2 人局下 rollout 的对手模型是"精确但随机"，多人局下多了一层
"手牌分配"的猜测——这也是后来把搜索从 2 人扩展到 N 人时收益最明显的原因之一
（Lv3 在 5 人局从 9.55 → 6.90，见 6 Nimmt 项目的 [搜索调参.md](../../20231022_6Nimmt/docs/搜索调参.md)、[多人重训.md](../../20231022_6Nimmt/docs/多人重训.md)）。
