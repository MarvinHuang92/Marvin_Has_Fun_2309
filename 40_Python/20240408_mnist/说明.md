# MNIST 手写数字识别（2024-04-08）

用 PyTorch 从零搭的**手写数字识别练习**：同一套「配置 + 训练框架」，分别跑**多层感知机（MLP）**和**卷积网络（CNN）**做 10 分类，用来对比两种结构。

代码风格是「配置驱动」：超参全写在一个文件里，「框架」只负责取数据/建模型/训练/预测，靠改配置开关来切换任务。

## 运行流程

```
number_classification.py   （配置 + for b in range(training_batch) 循环）
        │
        └─> neural_network_mnist.main(task_type, current_batch, plot)
              1. calcSampleRange()   算出本轮样本下标区间
              2. get_data()          npy 切片 → Tensor（CNN 时 np.expand_dims 补通道维）
              3. create_model() / load_model()      新模型学习率 ×10
              4. training_model()    CrossEntropyLoss → softmax_epoch() 迭代
              5. save_model()        写 model_mlp.pth / model_cnn.pth
              6. predict()           torch.max 取 argmax，打印误差、画散点图
```

**批量训练的学习率策略**：第 1 轮用 `learning_rate × 10` 新建模型，第 2 轮起 `task_type` 自动切成 `training_existing_model`，加载上一轮存下的模型、学习率恢复正常值 —— 相当于「先大后小」。

## 两个网络

| | MLP | CNN |
|---|---|---|
| 类 | `Network_2_hidden_layer_for_image` | `Convolve_Network_3_kernel` |
| 结构 | Flatten → `784→312→256→10`，层间 ReLU | `Conv(1→12,k7) → Conv(12→24,k5) → Conv(24→6,k3)`（均无 padding）+ `MaxPool2d(2)` → Flatten → `Linear(384→10)` |
| 维度变化 | — | 28→22→18→16→**8**，`6×8×8 = 384` |
| 参数量 | **327,618** | **12,976** |
| 优化器 | Adam | SGD |
| 保存文件 | `model_mlp.pth`（1.31 MB） | `model_cnn.pth`（56.7 KB） |

### 现存模型的实测准确率

| 模型 | 训练过的 256 条（下标 0~255） | 没见过的 1024 条（下标 10000 起） |
|---|---|---|
| `model_mlp.pth` | 100.00% | 82.62% |
| `model_cnn.pth` | 95.31% | 79.30% |

**只有 ~80%，是因为这份代码只训练了 2 个 batch（2 × 128 = 256 条样本）**，属于「跑通流程」的演示级模型，不是真正的 MNIST 结果（正常应该 97%~99%）。

想认真训练：

```python
# number_classification.py
task_type = "training_new_model"
training_batch = len(x_train) // batchsize_tr    # ≈ 468，即把 60000 条全用上
```

（CNN 那个结构没有 padding、参数只有 1.3 万，想更高精度建议多加通道/层、加 padding 和 BatchNorm。）

## 注意 / 已知问题

1. **必须在 `20240408_mnist` 目录下运行**（相对路径 + `sys.path` 两条原因）。
2. **分类任务打印的 MSE/RMSE 参考价值不大**：`predict()` 里算的是「预测数字 − 真实数字」的平方，不是准确率。准确率只在训练时由 `softmax_epoch()` 打印。
3. `create_model()` 只在 `hidden_layers == 2` 分支里建模型，其它取值会 `NameError`；CNN 的创建也嵌在这个分支里。
4. `model_visualization` 导出 ONNX 时 `dummy_input` 的维度是按全连接层拼的，**对 CNN 不成立**；而且需要额外装 `onnx`。
5. `softmax_epoch()` 里 `optimizer.step()` 在 `backward()` 之后、`zero_grad()` 放在循环末尾 —— 能正常工作，只是顺序不常规。
6. 拼写遗留：`netowrk_type`（network）、`polling_layer`（pooling）、`mpl_test.py`（mlp）。
7. 换机器后 `x_train.npy` 需要先解压 `x_train.zip`。
