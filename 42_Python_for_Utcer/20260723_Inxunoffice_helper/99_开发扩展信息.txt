python docx 库提取文字,除了段落,表格,页眉页脚,还有其他需要提取的吗?

除了段落、表格、页眉页脚，使用 python-docx 提取完整文字时，‌必须额外处理脚注/尾注、超链接文本、文本框（形状内文字）及目录内容‌，否则会导致信息缺失 。‌‌
核心遗漏项与提取要点

    ‌脚注与尾注‌：常含关键注释或参考文献，python-docx 无直接属性，需遍历 doc.part.rels 解析 footnotes.xml/endnotes.xml 或通过底层 XML 提取 。
    ‌超链接文本‌：链接锚点文字虽在段落中，但需单独识别 run.hyperlink 以保留 URL 关联信息，避免与普通文本混淆 。
    ‌文本框/形状内文字‌：嵌入在段落或单元格中的 InlineShape（非图片类）可能包含独立文本块，仅遍历 .text 会丢失这部分内容，需检查 inline_shapes 并解析其内部文本运行 。
    ‌目录内容‌：目录本质是特殊域代码生成的段落，常规遍历可提取文字但会丢失层级结构，若需结构化目录需识别 TOC 样式或域标记 。
    ‌页码与页眉页脚中的动态域‌：部分页眉页脚含 { PAGE } 等域代码，直接提取可能显示为代码而非实际数字，需视需求决定是否清洗 。‌‌

补充说明

    ‌图片本身无文字‌：图片不包含可提取文本，但若需图片中的文字（OCR），需结合其他库（如 pytesseract），python-docx 仅能提取图片二进制数据 。
    ‌公式与特殊符号‌：公式通常以对象形式存在，提取出的可能是乱码或空字符串，纯文本场景下往往忽略或需特殊解析 。
    ‌提取顺序建议‌：若追求“阅读顺序”完整文本，标准做法是遍历所有 sections 中的页眉页脚 + 主文档 paragraphs（含脚注引用标记）+ 单独提取脚注/尾注内容追加至对应位置；表格按自然顺序穿插在段落流中处理 。‌‌

若仅需“可见纯文本”做简单分析，遍历 doc.paragraphs 和 table.cells 通常覆盖 90% 内容；若需‌数据完整性‌（如归档、法律取证），务必补充脚注、尾注及文本框内容 。‌‌
